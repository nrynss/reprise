# Implementer handoff: session reconciler

Built the settle path for ended live sessions. The work owns
`internal/broker/reconcile.go` and its test beside it only.

## What it built

`internal/broker/reconcile.go` holds a `Reconciler` behind consumer
declared seams. One `Reconcile` call reads the provider duration,
settles the mint time hold to the real cost on both ceilings, closes
the lease at the provider number, writes the duration on the session
row, and persists the stereo recording privately. Over cap sessions
alert and still settle, because money owed is a fact.

The job kind is `reconcile` with `Idempotent: true` and `MaxAttempts:
3`. The input rides on the progress snapshot, so `Resume` rebuilds the
read from the interrupted record alone.

Exactly once rests on a durable claim row the file owns. The claim
winner settles. A loser reviews instead of spending twice. A resume
derives the money state from the lease row. A reconciled lease proves
the money path ran. A closed lease proves the budget settle ran,
because the close runs after it. Any other claimed state stops for
review with the hold untouched. A failed settle frees the claim, so a
retry may take it. Nothing after a booked settle frees it.

`internal/broker/reconcile_test.go` pins the done criteria with real
stores and no network. Recorded provider bodies decode through the
real parser. Three sessions settle against a real keyed budget and a
real lease manager, and the suite asserts spent equals the exact real
cost with none held. A crafted interrupted job record reopens through
a real runner and settles exactly once. A pre claimed row with an open
lease settles nothing and raises the review alert. A closed lease
resume finishes without double booking. The stored recording reads
back byte equal, and the media route answers 404 without a grant.

The full gate passes in the worktree, including `go test -race`, the
web build, and the plan reference scan.

## What surprised it

The lease store offers no listing, so no code can match leases to
sessions by owner plus open window. The input therefore carries the
mint time linkage (lease id and reservation). A sweep over open
sessions waits on the link migration below.

The budget settle always books, even when the hold is gone. That is
why the claim guard exists, and why an ambiguous resume never
retries money.

The `Budget` seam the broker declares has no settle method, so the
reconciler declares its own `Settler` seam beside it. The keyed budget
satisfies both.

## Contract changes

Provider sessions reader. The reconciler declares `SessionReader` and
a flat decode shape with `duration_seconds`, `recording_url`, and
`timeline_url`. The recorded bodies in the test pin that shape. The
provider package should implement the seam over its sessions
endpoint. The live probe should confirm the field names first. If the
real names differ, only the decoder and the fixtures change.

Session row write. The reconciler declares `SessionStore` with
`SetConnectedSeconds`. The store owner should implement it against
the sessions table. The test fake shows the one update it needs.

Lease to session link. No diary column links a lease row to a session
row, and the broker still mints with an empty provider session id.
The voice pass should write the provider session id it learns, and
the store owner should add the lease and reservation link at mint.
Until then the caller passes the linkage in the job input, and no
sweep can run on its own.

End of session wiring. Nothing schedules the job yet. Whoever owns
the session end hook should start one `reconcile` job per ended
session with the input this file defines, and register the kind from
`Reconciler.Kind` under `KindName`.

Recording format. The recording persists as `audio/ogg` by default
and the content type is configurable. The live probe should confirm
the container before the alignment work depends on it.

No library issue arose. Keel `v0.3.0` carried the job resume, the
lease claim semantics, the keyed settle, and the private media serve
this work stands on.
