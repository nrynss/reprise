Commit `b80efebfb35e9909ec06a1fb009eb51a9c2fab9c` on branch `task/t7.45`, worktree `/home/nryn/work/reprise-wt/t7.45-impl`. Only `internal/privacy/` changed.

## What was built

Erase now ends through the same call the sweep uses. `sessionTarget.Delete` in `internal/privacy/erase.go` type-asserts the session client to a local `sessionEnder` interface (`EndSession`, same shape as the broker ender) and calls it. That lands on `SessionsClient.EndSession`, which writes `session.end` on the live socket before the record delete. A socket that is already gone still deletes, and a repeat end opens no new socket, both inherited from that shared path.

The assertion keeps a plain-delete fallback for clients without the end. Production always offers the end, since the binary passes `*assemblyai.SessionsClient` straight through. The fallback exists so the retention suite, whose double only terminates and which this task may not touch, keeps compiling and passing.

Tests: `internal/privacy/erase_end_test.go` adds `TestEraseEndsLiveSocketBeforeDelete` (real provider client, held socket, order pin `end` then `delete`, exactly one frame of `{"type":"session.end"}`, one server delete, episode rows gone, job complete) and `TestEraseDeletesWhenSocketAndRecordGone` (gone socket plus provider 404 still completes with rows gone). The scripted double gained `EndSession` and the fixture gained `openFixtureOn` so an erase can run against a live client.

## Surprises

Retention builds its erasure on the inner privacy service and shares the `privacy.SessionClient` type, so narrowing that interface to the end would have broken retention tests outside this task's paths. The assertion plus fallback avoids that without touching retention. No new spend path: the end sends no update, and the mint already reserved the session.
