Commit `3e6c08e` on `task/t3.1` in worktree `t3.1-impl`. It owns

## What it built

`internal/assemblyai/batch.go` holds the batch client. It uploads raw
audio, creates a transcription with `speech_models` set to the flagship
model plus `keyterms_prompt`, polls `GET` on a timer, and deletes by id.
`Get` keeps the raw body beside the parse. `Transcript.Deleted` proves
deletion from the marker text with no words, because provider deletion is
soft. Polling carries results. Webhooks never reach this machine.

`internal/transcript/` holds the timeline. `Merge` shifts user words by
the user offset and host words by reply start plus host offset, then sorts
by start with the user first on ties. `Keyterms` reads mention quotes
recent first, dedupes them, and drops blanks plus phrases over six words.
`Replace` swaps the episode `edit` words in one transaction. `Run`
reserves budget first, uploads, creates, waits, persists the receipt,
merges, stores, deletes, confirms with a fresh fetch, and settles. A
refused reservation returns before any provider call. `Kind` sets limit 2
with no idempotence and no resume path.

## What surprised it

Fixture sessions do not exist yet, so the 50 ms bar runs against a
generated 2 second clip schedule plus the recorded probe shapes instead of
recorded stems. The words table carries no speaker column, so `Replace`
stores timing only and the speaker stays in the live turn rows. The batch
create call takes `keyterms_prompt`, not the live `keyterms` field. A
receipt store failure skips the delete on purpose, so the provider copy
survives for an explicit retry.

## Contract changes

The wiring change should register `transcript.Kind` under the
`edit_transcript` name and call `transcript.Run` with a `Config` carrying
the diary writer, the batch client, a cost budget, the user stem bytes
with their seconds, the live host replies, and the alignment offsets. It
should point `SaveRaw` at the episode media area and mark the episode
failed when `Run` returns an error, since this change owns no episode
writes. `transcript.Load` returns the timeline ordered by start for the
editorial and editor changes. A delete failure after storing returns an
error with words already saved, so an operator retry would pay again.
That retry stays an explicit operator decision and never runs on its own.
The 50 ms bar needs a live remeasure once fixture sessions land, because
the scripted provider returns exact times by construction.

No library issue arose. Keel `v0.3.0` carried cost, job, id, and sqlite
as recorded.
