## What it built

`internal/analysis/` holds the render analysis pass. Eleven files.

* `analysis.go`. Package doc, the `rendered` source constant, chapter
  sizing constants, and one sentinel per failure condition.
* `provider.go`. Consumer seams. `Transcriber` carries upload, one
  creation call, wait, fetch, and delete. `Chapterer` carries the
  chapter call with token usage. `Uploader` pins the upload signature
  against the real batch client.
* `run.go`. `Run` reserves budget first, uploads the render, creates
  one transcription, waits, persists the receipt, stores rendered
  words at once, asks the chapter model over the rendered transcript,
  persists that receipt, stores chapters plus mentions, deletes the
  provider copy, confirms deletion with a fresh fetch, and settles.
  Any failure before the delete keeps the provider copy for an
  explicit retry and frees the reservation. `Kind` sets limit 2 with
  no idempotence and no resume path. `Estimate` prices batch audio
  plus a chapter token cap. `GatewayPrice` books usage at catalog
  rates from config.
* `chapters.go`. `SegmentWords` groups words into timed slices.
  `PromptText` states the three chapter rules outright.
  `NormalizeChapters` sorts drafts, pins the first chapter at zero,
  snaps every other start to its word, merges spans under ten
  seconds, and splits the longest spans until a long enough episode
  carries three chapters. Seeking to any returned start lands on
  stored words, because each start equals zero or a word start.
* `offsets.go`. `OffsetOf` maps a millisecond span to its rendered
  word index, with gaps taking the next word and drift past the end
  taking the last word. Entities keep the provider type as their
  kind. Key phrase occurrences read `keyphrase`, one mention per
  span.
* `store.go`. `ReplaceWords` stores source `rendered` and leaves the
  edit timeline untouched. `StoreAnalysis` writes the analyses row
  and the mentions in one transaction with replace semantics, so an
  explicit retry stores the same rows again.
* `scripted.go`. Scripted doubles for both seams, following the cover
  pattern. Tests run the whole pass offline through them.

## Pins, all offline

* The full run test moves real stem bytes from the committed
  sessions through the upload seam, buys words plus entities plus
  phrases plus summary on exactly one creation call, and asserts one
  call each for upload, create, chapters, and delete. It pins 40
  words, 4 chapters, and 4 mentions with exact offsets, both
  receipts kept, and one reserve plus one settle with a positive
  spend inside the reserve.
* The seek check reads stored chapters back and asserts every start
  past zero equals a stored word start.
* Refusal reaches no provider endpoint. Receipt failure skips the
  delete and releases. A readable copy after delete fails with the
  delete sentinel and never settles. Chapter failure keeps the copy.
* Mutation checks ran by hand. Forcing the first start off zero
  fails the shape test. Changing the source constant fails the store
  test, which compares against the literal value.
* The compat test pins a real batch client against the upload seam.

## What surprised it

The batch client covers upload, poll, delete, and confirm, but its
create call carries keyterms only and its parse keeps words only.
Entities, key phrases, the summary, and the chapter call need shapes
the client does not expose. This pass therefore defines consumer
seams and proves the full behavior through scripted doubles. The
production binding waits on the adapter extension below. No code
here speaks HTTP, so the single provider adapter rule still holds.

Chapter shaping needed one judgement call. Dropping a trailing stub
can take a long episode under three chapters, so the pass merges
first and then splits back to three. The round reviewer should read
that order as specified behavior, not as padding.

## Contract changes

### Provider adapter extension

The adapter needs an analysis create carrying entity detection, key
phrases, and summarization on the same request, plus a parse keeping
entities, highlight spans, and the summary response beside the words.
It also needs a chapter client over the gateway, taking the model id
as an argument, posting transcript text with a token cap, and
returning raw drafts with prompt and completion token counts. The
`Transcriber` and `Chapterer` interfaces in `provider.go` name the
exact methods and shapes. The compat test in `run_test.go` names the
upload half already satisfied.

### Wiring notes

Register `analysis.Kind` under the analysis job name. Serve the
render locator from the latest renders row for the episode plus a
media store read, with the duration probed from the stored bytes.
Read the gateway model id and the token rates from settings, never
from code, and point the receipt sink at the episode media area. The
sink hears two names, `transcript` and `chapters`.

### For memory consumers

Mentions carry `kind` as the provider entity type verbatim, or
`keyphrase` for phrase occurrences. `word_offset` indexes the
episode words with source `rendered` ordered by start. `quote`
carries the wording the keyterm boost reads. A rerun replaces the
episode mentions, so replant callback rows built on older mentions
after a retry. The analyses row stores chapters as title plus
`start_ms` items, the summary as headline plus bullets plus block
text, and entities and phrases with their millisecond spans.

### For export consumers

Read chapter lines from the analyses `chapters` JSON. It opens at
zero and every start matches a rendered word start. Take audio ids
and durations from the renders row as before.

## State of validation

Scripted doubles stand in for the provider throughout. The upload
body is real committed stem audio. The word schedule, entities,
phrases, summary, and chapter drafts are scripted. The chapter and
seek checks run against generated boundaries, and the suite states
that where each value comes from. A live remeasure against a real
render belongs with the adapter extension, once one creation call
can return every feature.
