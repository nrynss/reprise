## What the recording lane must add

Each session directory must gain `clips.json`: a JSON array with one entry
per streamed guest clip, such as
`[{"file":"user-a.wav","start_sec":3.412},{"file":"user-b.wav","start_sec":12.870}]`.
Each `file` is the clip base name. Each `start_sec` is the local clock
reading at the first clip sample, on the same clock the event log offsets
use, with millisecond precision or better. The driver matches entries by
file name, needs at least two, and fails loudly on any other shape. No
host stem is owed: host audio originates provider-side, so the two guest
clips form the pair, and their shared stream path latency cancels in the
gap. Once the record lands, `TestFixtureSessions` flips from the loud
evidence block to the 40 ms verdict with no driver change.
