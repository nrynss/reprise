## What it built

Upload opens now carry the session user id and media 404s carry
private no-store, both wired in `main.go`.

`withUploadOwner` runs inside the guest middleware, reads the
resolved user from the request context, and replaces the posted
owner on open calls only. Chunk, state, and complete pass through.
The stored blob carries the id the authorizer compares, so the
uploader reads its own bytes and a cookieless read still 404s. No
frontend change was needed. The literal `guest` value is now inert.

`withMediaRefusalHeader` stamps any bare 404 with `Cache-Control:
private, no-store` and leaves successful reads untouched. Unknown
ids and refused private reads answer identically.

`TestUploadOpenResolvesSessionOwnerAndRefusalCarriesHeader` pins it
end to end: open with literal `guest`, stored owner is the session
id, one chunk completes, owner reads exact bytes back, anon reads
404 with the header on blob and unknown id. A throwaway probe
against the bare handlers reproduced the defect first (deleted
after).
