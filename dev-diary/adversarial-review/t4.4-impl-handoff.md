## What it built

`internal/privacy/` holds publish, share, and erase. Nine Go tests
pin both sides of every behavior through a real SQLite file, a real
media store, and scripted provider doubles.

* **Publish** mints a fresh unguessable token on every call, marks
  the episode public, and marks the streaming render public. The
  export copy stays private. Publish refuses with `ErrNoRender`
  until a render lands, so a link never opens with dead audio.
* **Unpublish** marks the episode private, rotates the token so the
  old link dies, and returns every render blob to private.
* **Share** resolves a token to title, number, audio blob, and cover
  path only when the episode is public. Unknown, revoked,
  unpublished, and malformed tokens share one identical 404. The
  handler serves exactly two paths, metadata and cover, so no stem,
  transcript, thread, or second episode is reachable from a token.
  Audio streams from the media store, which serves the public blob
  with the immutable cache and 404s everything private.
* **Erase** fans out through the shared erasure library as the erase
  job kind. Targets cover the episode row with its cascade, every
  blob grouped under the episode plus every stem and render blob id,
  the cover file, the reconciliation rows for its sessions, the
  provider session, and every remaining batch transcript. The ref
  carries the full inventory, so a resumed run rebuilds its targets
  after the rows are gone. `ReErase` restarts a stuck erasure from
  the recorded ref with ownership checked against it.
* `web/src/routes/share/[token]/` holds the public page with its
  client and eight vitest cases. `web/src/routes/privacy/` holds the
  plain words page. Three route level playwright proofs cover the
  published fixture, the revoked fixture, and the privacy copy.

## Pins, all offline except the store

* Publish serves the opus render signed out with the public
  immutable cache while stems and the export copy 404. Unpublish
  rotates the token and returns the render to private.
* Share metadata and cover serve 200 published and one identical 404
  for revoked, malformed, and unknown tokens. Five non share paths
  404.
* Erase leaves zero rows in every diary table, zero media rows, zero
  files, and zero cover for the erased owner, ends the scripted
  session, deletes the scripted transcript, and leaves the second
  owner untouched row by row and blob by blob. A refused provider
  delete fails the job stuck naming only its transcript, and a retry
  finishes it.
* Restart opens a fresh runner on the same job ledger mid erase and
  finishes, with only unconfirmed targets deleting again.

## What surprised it

* The media store exposes no visibility flip, so publish flips the
  media row directly. Bytes and ids stay stable across the flip.
  A store level flip would serve every consumer and belongs in the
  library plan, not here.
* Render and stereo blobs already group by episode, so one media
  group query catches the provider stereo copy with no new tracking.
* The cover lives as a file, not a blob, so the share cover needs
  its own endpoint with the cover directory as config.
* The transcript and analysis passes already delete their provider
  copies, so erase hunts only what remains, namely analysis rows and
  session rows.

## Contract changes for wiring

* Open the service with the shared handle, the media store, the
  cover directory, the provider clients, and an ownership check, then
  open the job runner with `Kinds[erase.KindName]` set to
  `svc.Eraser().Kind()`, then call `BindRunner`. Adapt the guest
  service with `IdentityOwns`. Mount `svc.Handler()` on the publish,
  episode, and share patterns the route table already names.
* `DELETE /api/episodes/{id}` answers 202 with the erasure job id.
  The client follows it over the job stream. A stuck job needs a
  retry control calling `ReErase`, which no route exposes yet.
* Any future receipt blob grouped by episode joins the fan-out
  automatically. A receipt stored anywhere else needs its id in an
  episode row first.
* Live remeasure is owed. Provider doubles stand in throughout, and
  the signed-out share checks ran handler level. A workstation must
  still open a published link and a revoked link against the box,
  because the box challenges its own address.
