# T2.1 implementer handoff

Built the session broker behind seven ordered checks. The work owns
`internal/broker/` and `internal/assemblyai/token.go` only.

## What it built

`internal/assemblyai/token.go` holds a token client. `Mint` sends
`GET /v1/token` with `expires_in_seconds=60` and
`max_session_duration_seconds` set to the session cap. It caps the input
within 60 to 10800 seconds. Failures wrap one sentinel and never carry
the key.

`internal/broker/broker.go` holds the broker. `POST` runs gate (through
`Route`), kill switch read at request time, guest quota from the
`sessions` row count, owner plus global ceilings reserved for the full
cap at $4.50 per hour, a lease open counted to quota, the token call,
then the diary rows with a 201 carrying token plus session config. Any
failure after the reservation releases it and closes the lease, so a
refusal holds nothing. Refusals answer through `wire.WriteError` with
stable codes. No response body carries the key.

`internal/broker/diary.go` holds diary access. It counts sessions per
owner and inserts one recording episode with its session row. The
provider session id stays empty until the voice pass learns it. A
session insert failure removes the episode it just made.

`internal/broker/broker_test.go` pins both sides. The pass test drives
the real token client against a fake server and asserts one token, one
reservation, one lease and one row. Eight refusal tests cover each
check, with the ceiling check split into owner and global. Cleanup
tests assert zero held reservations and zero open leases after token,
config and store failures.

Gate passes in the worktree. `go test -race` passes for the touched
packages and the full `./tools/check.sh` run ends OK.

## What surprised it

The `sessions` row needs an `episodes` row first, because the foreign
key demands it. The broker therefore begins a recording episode on each
mint. Episode numbers come from `MAX(number)` per owner.

The keyed budget refuses unknown owners, so the broker ensures the
owner ceiling on first use from `OwnerSessionLimit`. Later admin edits
to that ceiling survive, because the broker only writes it when no
ceiling exists yet.

The lease manager settles its estimate through its own meter at open.
The broker instead reserves once on the durable ceilings and hands the
manager a bookkeeping meter, so one session holds exactly one
reservation. The meter is unexported and documented where it lives.

## Contract changes

Host config seam. The broker declares `SessionConfig` with system
prompt, greeting and keyterms, plus a `ConfigBuilder` interface that
builds it from stored rows. The host prompt change should implement
`BuildSessionConfig` on its builder. A stub serves until then. If the
host change wants its own shape, it can adapt to this struct without
touching the broker.

Main wiring. Nothing in this change mounts the route. Whoever wires it
should chain gate outermost, then guest middleware, then the broker,
and mount the result at `POST /api/sessions`:

```go
protected, err := broker.Route(gate, rule)
handler := identityService.Middleware(protected)
mux.Handle("POST /api/sessions", handler)
```

Construction needs the shared database with the diary schema open,
`flag.Store`, a `KeyedBudget` over a cost store limited to
`DailySpendCents`, a lease quota and lease store, the token client with
the AssemblyAI key, a config builder, the diary, `SessionMaxSeconds`,
`GuestMaxSessions`, and a per-owner default limit. Suggested defaults:
global limit from settings, owner default equal to a few session
estimates, quota sized for expected concurrent takes.

Reconcile seam. `Broker.Leases`, `Broker.Budgets` and `Broker.Diary`
expose the rows and holds the reconciler settles. The reconciler
should settle the held reservation to real connected seconds and mark
the lease reconciled.

Known gap. No diary column links a lease row to a session row. The
broker sets `provider_session_id` empty at mint. Reconciliation must
either match by owner plus open window or request a store migration
adding the link. The migration belongs to whoever owns the store
schema, not to this change.

No library issue arose. Keel `v0.3.0` carried gate, cost, flag, lease
and wire as recorded.
