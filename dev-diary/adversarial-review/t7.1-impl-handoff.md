## What it built

Episode list, detail, decisions, done, session end, and threads
handlers behind owner checks, with mark done starting one render job.

`internal/episode/` gains a `Service` with owner-scoped list, get,
proposals, append-only decide (latest wins), render request guarded
first on draft to rendering (a repeat tap reports
`ErrIllegalTransition` and starts nothing, a never-started job fails
the episode for explicit retry), and repeat-safe session end
recording. Unknown and foreign ids both report `ErrNotFound`.

`internal/api/` gains episode list (200), detail with proposals
(200), decisions (200), done (202 with job id), session end (200
with recorded close), and threads (recurring names plus circled
topics, all counts from stored rows). All answer `no-store`, all
check the guest first (401), refusals use stable envelope codes.
`handlerFor` now matches method plus pattern. Publish, unpublish,
and erase stay on the stub.

## Surprises

`handlerFor` matched pattern alone, so wiring `GET
/api/episodes/{id}` would also have served `DELETE
/api/episodes/{id}`. It matches method plus pattern now, pinned by a
test on the DELETE stub. The threads query needs the `resolutions`
table, but no production path runs `memory.Migrate`. Tests run it.

## Contract changes

`main.go` (T7.2's) must construct one `episode.Service` (database
plus job starter, render kind name, render resolver behind the
renderer seam), pass it to the episode and session end constructors,
pass the diary database to the threads constructor, set the three
new dependency fields, and call `memory.Migrate` on the shared
database before serving threads.
