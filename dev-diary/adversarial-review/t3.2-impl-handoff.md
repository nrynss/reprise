# Implementation handoff

Commit `1f778d3c2183758da0ef105171e7547bfca4df16` on `task/t3.2` in worktree `t3.2-impl`. It owns `internal/gemini/` and `internal/editorial/` only. The gate passes in that worktree, including `go test -race`, staticcheck, and the full web checks.

## What it built

`internal/gemini/` holds the model client. `NewClient` opens Vertex AI from settings with the service account key. `GenerateEditorial` sends both stems as inline Opus with the numbered timeline and returns JSON under a response schema. `NewTestClient` binds a scripted answer so tests run offline with no key and no network. The prompt orders delivery over transcript for the cold open and carries the same rule the listening probe proved.

`internal/editorial/` holds the pass. `Run` reserves budget first and refuses before any model call. It validates every span against the loaded edit timeline. Dangling spans drop with a log line and never store. Cuts store accepted with a decisions row. The callback stores a mention row of kind `callback` with its word offset plus a callbacks row, so the next opening cites stored data. Model failure or unusable JSON still leaves a renderable draft with no cuts and a plain title. `Kind` sets limit 2 with no idempotence and no resume path.

## What surprised it

Fixture sessions do not exist yet, so the timeline runs against generated edit words spaced 300 ms apart. The words table ids remint on every replace, so proposals point at positional offsets instead of row ids. Offsets stay stable across reruns while ids do not. The cold open schema asks for a delivery reason, which the editor can show beside the preview. The minute rate is a placeholder at a quarter cent per audio minute until billing data lands.

## Contract changes

The wiring should register `editorial.Kind` under the `editorial` name and call `editorial.Run` with a `Config` carrying the diary writer, the Gemini client, a cost budget, the model id from settings, both stem bytes with their seconds, and a receipt sink. It should mark the episode failed only when `Run` returns an error, since model failure returns a fallback result with no error. The editor change reads proposals of kinds `cold_open`, `cut`, `title`, `show_notes`, and `callback`, with ranges as offsets into `transcript.Load` order. The render change reads accepted cuts and the cold open from the same rows. The memory change reads callbacks joined to mentions for the next opening. A revert of a callback proposal should also clear its callbacks row, and that belongs to the editor change.

No library issue arose. Keel `v0.3.0` carried cost, job, id, and sqlite as recorded.
