## What it built

`internal/api/routes.go` now mounts instead of only listing. The route
table gains the three admin patterns (`GET /api/admin/limits`,
`POST /api/admin/limits/pause`, `POST /api/admin/limits/owner`), taken
from the limits package constants so the table and the handler cannot
name different paths. `Mount` wires each implemented handler behind the
spend gate outermost, then the guest session middleware, then the
handler: broker at `POST /api/sessions`, the limits handler at the admin
trio, the chunked upload handler at `/api/uploads` plus its slash form,
the blob store at `GET /media/{id}`, and a closure over
`stream.Broker.ServeTopic` on `job.Topic(id)` at
`GET /api/jobs/{id}/events`. Routes with no handler stay on the
`not_implemented` stub, including `POST /api/sessions/{id}/end`, which
no change implements yet. `Mount` refuses to wire when the two owner
ceilings disagree, when a handler arrives without the gate or the guest
middleware, or when the rule cannot protect a route. `Register` keeps its
stub-only behavior for the whole table.

`cmd/reprise/main.go` adds registration only. `wireAPI` opens one SQLite
file (`data_dir/reprise.db`), migrates the diary schema, then opens the
guest sessions, the spend ledger with the daily ceiling, the keyed budget
over it, the runtime switches, the lease quota and lease rows, the token
client, the session diary, the broker, the limits service behind
`StubOwnerAuth`, the media index and media store with the identity
authorizer, the upload handler with `BasePath` from `api.UploadBasePath`,
the spend gate, and the stream broker, then calls `api.Mount`. One value
feeds both `OwnerSessionLimit` and `OwnerDefaultLimit`, so the broker
provisions exactly what the spend view subtracts from. Boot, drain,
health, and the app shell are untouched. The drain registry stays nil.

`web/src/lib/api/types.ts` mirrors the three admin patterns in table
order. The server test regenerates `routes.json`. `stub-refusal.json` is
byte-identical, since the probed stub route is still a stub.

## Pins

The api tests mount recording handlers behind a real gate and a counting
guest stub. They pin the two owner ceilings refusing on mismatch, the
gate and middleware being required, every mounted route reaching its
handler exactly once through the chain with the middleware mark present,
the job events route answering `text/event-stream`, the end and gallery
routes staying on `not_implemented` without touching the chain, and a
gate refusal reaching neither the middleware nor the handler. The main
tests pin the cents to nanodollars conversion with its negative and
overflow refusals, and the host adapter serving the opener config from an
empty season. A live boot proved the wiring end to end: 403
`owner_required` on the admin snapshot, 501 on the end and gallery
routes, 400 from the upload handler, 404 from the blob store on an
unknown id, 200 SSE on the job events route, and a minted guest cookie on
the events response. No live session was started, so no provider spend
occurred.

## What surprised it

The broker handoff snippet wraps the gated broker in the guest
middleware, which puts the guest layer outside the spend gate. This
change calls `Protect` over the middleware instead, so a refused request
never mints a guest row. The order follows the task text.

Nothing implements `broker.ConfigBuilder` yet, so `main.go` carries a
six line adapter from `host.Load` to the broker session shape. It belongs
to whoever owns the seam only if they want it moved. It compiles against
both sides today.

A zero daily spend ceiling stops the process, because the broker rejects
a non-positive owner limit. A zero ceiling cannot boot into an
all-refuse posture today.

## Contract changes and notes for the next developer

The media store admits the default media library types plus `audio/mp4`,
which the default set leaves out and the render needs for its AAC blob.
The list is spelled out in `main.go` because the library exposes no
append form. A library release that adds types will not appear here
until the list is edited.

Upload staging lives at `media_dir/upload-stage`. The database file is
`data_dir/reprise.db`, matching the backup default. The lease quota is a
constant of 8 concurrent sessions. The shared gate rule allows bursts of
16 per client and 256 global per minute. Each is a starting posture, and
each changes in `main.go` alone.

The drain still passes nil for the session registry. Passing the broker
lease manager is one argument once someone owns that behavior change.

No library issue arose. Keel `v0.3.0` carried the gate, the upload and
media handlers, the stream broker, and every store as recorded.
