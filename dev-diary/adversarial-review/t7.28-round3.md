`internal/episode/playback.go` and `internal/api/episodes.go` are both owned. The read calls `Get`
first, so an unknown or foreign episode answers `ErrNotFound` before any job row is read. It then
reads `LastKindJob`, the same read the transcript outcome uses. The wire reuses
`transcriptOutcomeJSON`, and the field is `omitempty`, so a detail with no editorial pass carries no
key. The error text reaches only the owner, as the transcript pass error already does. Gating the
read on the transcript kind is sound, since only the transcript pass starts the editorial pass.

gets 404 on the first owner's detail, and that body holds neither the job id nor the failure text.
The second owner's own detail carries no `editorial_outcome`. An anonymous request is refused.

ended in `error`, `interrupted` or `cancelled` still read `Working · …`. It now reads "The pass
stopped before it finished." unless a note is known. The refresh interval picks up a note that the
recheck fetched after the stream ended, so a pass that fails while the gallery is open shows its
reason within half a second. I checked that path by reading `refresh()` and the 500 ms timer.
The note path misses one real case, finding 1.
