## What was built

A second reconcile for a settled session stores nothing new. One session
runs under an in-process lock, so two end jobs cannot both pass the empty
media id check. The durable guard is the claim row. Once it holds a
recording id or a timeline id, a later pass reuses that id. It does not
fetch again and it does not write another blob.

The timeline bytes persist on receipt as a private `application/json`
media row in the episode group, beside the stereo recording. The expiring
URL stays as metadata only. Money still settles once. The `turns` table
is untouched.

`TestReconcileRepeatEndStoresNothingNew` reconciles one session twice and
reads the media table. It expects one `audio/ogg` row and one
`application/json` row. Dropping both `recordingMediaID == ""` and
`timelineMediaID == ""` checks makes that test fail. The second pass
returns new media ids. The concurrent pin
`TestReconcileConcurrentEndsStoreOnce` fails the same way. Both guards
were restored after that check.

`TestReconcileSettlesEveryHold` reads the stored timeline bytes back.
`TestReconcileTimelineColumnMigrates` adds the claim column on an older
table and still stores one pair.
