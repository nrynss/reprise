# T3.3a implementation handoff

Commit `5e9cc9584c57273b28d667864de6e650e286e2e5` on `task/t3.3a` in worktree
`t3.3a-impl`. It owns `web/src/routes/episode/[id]/edit/` and
`web/src/lib/editor/` only. The full gate passes in that worktree after
`npm ci`, including the route Playwright proofs.

## What it built

Each non-cut proposal kind gains a one-action revert beside its display,
following the cut-revert pattern: a decision row is written locally first,
then posted as `{ proposal_id, decision: "reverted" }` to the decisions
endpoint, and a refused POST changes nothing on screen.

- Cold open: `revertColdOpen` sets a reverted flag. The range stays on
  screen struck through with its reason, the preview control hides, and
  the render reads the flag plus the `prop-cold-open` decision row.
- Title: `revertTitle` falls back to the plain episode number in the
  heading. The proposal stays on screen struck through.
- Show notes: `revertNotes` falls back to empty. The screen gains a show
  notes section, which did not exist before. The proposal stays on screen
  struck through.
- Callback: `revertCallback` clears the callback text and quote, sets the
  reverted flag, and sets `callbacksCleared`, which stands in for the
  cleared `callbacks` row until the endpoint serves it. The original text
  stays on screen struck through with a cleared notice.

A second revert of the same kind writes no new row and changes nothing.
Every new control is a native button with an accessible name, and the
`?gate=1` proof still passes both library gates.

## What surprised it

The Chaaya `0.2.0` transcript module carries a revert affordance for cuts
only (`TranscriptEditor.revert`). Non-cut proposals have no library cut
to revert, so this change reuses the decision POST shape and the
local-first pattern rather than the method itself. No library gap arose,
so no issue was filed.

The snapshot already carried `notes` but the screen never rendered it.
The new show notes section is the first place it appears.

## Contract changes

The screen posts `prop-cold-open`, `prop-title`, `prop-notes`, and
`prop-callback` with decision `reverted` to
`/api/episodes/{id}/decisions`, the same shape as the cut reverts. The
render change reads the `prop-cold-open` decision row (plus the reverted
flag in the decision state) to start at the top, and the memory change
reads the `prop-callback` row plus the cleared callbacks row for the next
opening. Both endpoints are stubs today. The screen works fully against
fixtures until they serve.
