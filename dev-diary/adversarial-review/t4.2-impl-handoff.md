## What it built

`internal/memory/callback.go` chooses the next episode opening from
stored rows and stores the pick.

* `Select` ranks contenders in priority order. Open commitments come
  first and oldest, then recurring names by span, then circled topics
  by span. It stores the winner as a `callbacks` row pointing at the
  source mention, unused, under the just finished episode.
* Agreement means the planted row points at the same mention row as a
  contender, or its quote folds to the same key through the shared
  normalizer. The first agreeing contender in priority order wins, so
  the planted pick keeps the tier behind it. A stale plant that
  matches nothing loses, and its row leaves the unused list for its
  own episode.
* The pick never repeats the most recently stored callback by folded
  quote. The previous choice query ignores rows under the current
  episode, so the plant for this episode cannot block itself. A season
  with nothing worth opening on returns nil and stores nothing.
* `MarkUsed` flags one row spoken, scoped to the owner. An unknown id
  fails with `ErrNotFound`.
* `Selection` carries kind, callback id, mention id, episode number,
  quote, offset, and whether the pick honors the plant.

`internal/memory/callback_test.go` pins the contract offline. Seven
tests seed four episode seasons. The first test selects the episode
one dread and renders it through the greeting builder, asserting the
greeting names episode one with the quote. The rest pin plant
agreement by shared quote, stale plant rejection, no repeat across
two selections, tier fallthrough after a close, the nil season, and
the used flag with the unknown id case.

## What surprised it

* Thread hits carry episode and offset but no mention id, so the
  selector resolves the source row with an oldest match lookup over
  the owner mentions. Commitment contenders already carry their row
  id and skip the lookup.
* The first cut of the no repeat rule read the latest row under any
  episode. That blocked the agreeing plant, because the plant itself
  was the latest row. Scoping the previous choice to other episodes
  fixed it, and the agreement test failed before the fix and passes
  after, so the pin holds.
* The greeting builder reads the oldest unused row and cites the
  mention episode, not the callback episode. Storing under the just
  finished episode therefore never leaks into speech. This matches
  the editorial pass, which plants under the episode it read.

## Contract changes

### For the greeting consumer

* Call `memory.Select` with the owner and the just finished episode
  id once the analysis and memory passes store that episode rows.
  Call it after the editorial pass, because the editorial plant must
  already sit in `callbacks` for agreement to see it.
* Serve the host greeting from the stored row as today. `Select`
  leaves its row unused, so nothing changes on the read path.
* Call `memory.MarkUsed` with the owner and the spoken callback id
  after the host speaks the greeting. Until then a restart keeps the
  opening, which is the safe direction.
* When `Select` returns nil, serve the first episode opener. The
  season holds nothing worth opening on.
* `Selection.Kind` reports which tier won. The gallery may show it
  beside the opening. The quote and episode number stay the spoken
  surface.
* The selector deletes rival unused rows under the same episode
  before storing. A repeated run for one episode stores exactly one
  row. It never touches used rows or rows under other episodes.

No library issue arose. The change reads the existing readers and
the existing `callbacks` schema, and it adds no dependency.
