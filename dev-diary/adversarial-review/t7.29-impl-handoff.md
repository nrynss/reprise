## What I built

### The finish chain (`cmd/reprise/finish.go`)

- Mark done starts the render through `jobs.StartEpisodeKind`. The job is stamped with its episode
  before the request answers, so the detail names the render from its first read.
- The render work is chained. A finished render becomes the newest render row and moves the episode
  to `analysing` under the schedule lock. Then `advance` starts the analysis and cover passes. A
  render that finishes on an episode already past `rendering` starts nothing.
- Every pass after the render is stamped with `render_id`. `advance` starts a pass only when no pass
  of that kind exists on the newest render (`episode.LastRenderKindJob`). So a repeat mark done, a
  repeat render completion and a boot recovery each start nothing new.
- A done analysis starts the marking pass. The episode moves to `ready` once analysis and marking
  both stop. A failed analysis skips marking and still ships, because the render already plays.
- The cover never holds the episode. A cover pass that fails, or a cover a restart interrupted,
  stores the plain cover through `cover.Run` with a local model that always refuses. That value is
  also its budget and books nothing, because it calls nothing paid.
- A pass's own job record reads `running` until its work returns. Two passes settling together
  would each wait on the other. `jobs.settled` keeps each settled outcome under the schedule lock
  until the record catches up.
- A pass kind at its limit refuses a start. `runAdvanceLoop` retries every 30 seconds.
- `withLinkage` restamps every progress report. Keel replaces the whole snapshot on each report, so
  the render's stage reports dropped the episode linkage.

### Restarts

- The render kind keeps `render.KindOf`'s limit and idempotence, with `MaxAttempts: 3` and a resume
  that rebuilds the chained work. `recoverFinish` fails a rendering episode whose render stopped for
  good, settles one whose render finished, and starts a render that never started. Then it advances
  every analysing episode.
- Paid kinds stay non-idempotent with no resume. None reruns. `settleInterrupted` replaces
  `failInterruptedEpisodes`. An interrupted transcript still fails its episode. An interrupted
  editorial pass now leaves the draft in place, so it can still ship with its plain title. An
  interrupted cover stores the plain cover. Interrupted analysis and marking ship the episode.

### Rendered words name their render

- `internal/analysis` owns a new namespaced migration, `rendered_sources`. It holds one row per
  episode naming the render its rendered words came from, and cascades from the episode and the
  render.
- `analysis.ReplaceWords` now takes the render id and writes words and link in one transaction.
  `analysis.Config.RenderID` is required before any paid call. The locator reads that exact render.
- `episode.RenderedWords` returns words only when the link names the newest render.

### Detail and gallery

- `episode.Service` gains `RenderOutcome`, `AnalysisOutcome` and `MemoryOutcome`, plus
  `NewestRenderID`, `LastRenderKindJob`, `AnalysisKind`, `MemoryKind` and the optional
  `EpisodeStarter` seam.
- `internal/api/episodes.go` sends `render_outcome`, `analysis_outcome` and `memory_outcome`.
- `threads.ts` `galleryPass` sends rendering and analysing episodes to `finishPass`. The card
  follows the render, then the analysis, then the marking pass. A running pass already carries its
  done line, so the card never reads "Ready" before the episode does. With no pass named yet, it
  follows the transcript pass with a waiting line. A live rendering or analysing row rechecks the
  detail when its pass stops, and takes the state the detail reads.

### Wiring split

- `privacy.go`, `seed.go` and `export.go` each hold an empty kinds hook and an empty mount hook.
  `features()` in `main.go` names all six, and `wireAPI` calls them.
- The kinds hooks get `kindWiring` (DB, media store, settings). `mergeKinds` joins them with the
  core kinds before the runner opens and refuses a repeated name with `errDuplicateKind`.
- The mount hooks get a context and `routeWiring`: mux, spend gate, outer rule, guest middleware,
  DB, runner, media store and settings. A hook error refuses the boot by feature name.
- `kindEditorial`, `kindAnalysis` and `kindMemory` read the episode constants.

## What surprised me

- `render.KindOf` sets no `MaxAttempts`, so Keel never resumed a render at all.
- Each render stage report replaced the stored progress, so the descriptor `Resolver.Resume` reads
  was gone after the first stage. The detail could not find a running render either.
- A render that reused an older row appended nothing. After alternating inputs, the newest row
  named a different file than the render produced. The chain appends the reused row again with
  `render.StoreRender`.
- Marking must follow analysis. `analysis.StoreAnalysis` deletes every mention of the episode, so a
  marking pass that ran first would lose its commitments.
- The base commit tracks review probes as Go files under `dev-diary/probes/`. Two directories hold
  two packages each, so `go list ./...` fails and prints nothing. In `check.sh`, `GO_PKGS` is then
  empty. I listed `./cmd/... ./internal/...` instead, which is the same product set.
- Stuck `rendering` episodes on the box carry render jobs with no linkage. After deploy,
  `recoverFinish` starts one render for each, and their paid passes then run once. None of those
  passes ran before, so nothing reruns. The owner should expect that spend.

## How the "Done when" is proved

- **Mark done to ready, stored rows, no second chain:** `TestMarkDoneReachesReadyOffline` in
  `cmd/reprise/finish_test.go`. It boots `startJobs` and serves `api.NewEpisodes` over
  `episodeConfig` behind the guest middleware, as the binary wires them. Doubles answer Gemini and
  the batch transcriber, so no network is needed. ffmpeg renders the fixture stems. It posts mark
  done and waits for `ready`. Then it reads the chapters, cover and commitment rows, and the render
  link. It checks one job per kind, no held reservation, and all three outcomes done. A second mark
  done answers 409. A replayed render completion plus `advanceAll` starts nothing.
- **Hook files and duplicate kinds:** `TestFeatureHooksAreWired` and `TestDuplicateKindRefusesBoot`.
- **Failure paths:** `TestFailedAnalysisStillShips` and `TestCoverFailureLeavesPlainCover`.
- **Restarts:** `TestRestartFailsInterruptedPaidJobs`, `TestRestartInterruptsPaidPassesAndShips`,
  `TestRestartKeepsDraftAfterLostEditorial` and `TestRestartResumesRenderIntoTheChain`.
- **Render stamp:** `TestRenderStampsItsEpisode`, plus `TestRequestRenderNamesTheEpisode` in
  `internal/episode`.
- **Words follow the newest render:** `TestRenderedWordsFollowTheNewestRender`,
  `TestReplaceNamesTheRender`, and the extended `TestEpisodeDetailServesWordsStemAndRender`.
- **Gallery card:** `web/src/routes/threads/gallery-finish.test.ts` walks a card from rendering
  through analysing to ready. It proves no snapshot reads "Ready" before the row does. Dropping
  `RENDERED_NOTE` from `finishPass` fails two of its cases.
