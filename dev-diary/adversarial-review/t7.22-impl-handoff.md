browser posts no body, so the handler now reads the raw bytes: empty
or blank records the zero close with 200, and malformed JSON still
answers 400 invalid_request. The shared body decoder stays strict,
so the decisions route still refuses an empty body. The recorded
zero close flows through the existing settle rule that skips rows
with no provider id. Only the server moved. The browser is untouched.

call posts no body and the socket never reports a provider session
id, so the shaped body has no live writer. No contract change is
needed. Settlement of empty closes follows the rule already in the
code.
