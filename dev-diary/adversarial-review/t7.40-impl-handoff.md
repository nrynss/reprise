## What was built

End asks before it stops the take. Cancel drops the ask and leaves the
take recording. Confirm uses the same end path as before. The provider
socket ends at once. Closing the tab during the ask still sends
`session.end` and the beacon. The ask is in the page, so it does not
delay `pagehide`.

A short upload still finishes on the record page, then the draft move
runs there. A slow upload leaves for `/processing` within a quarter
second, before that upload finishes. The move is a client navigation.
The same uploaders keep running, so the bytes are not dropped. The
processing screen draws that upload first, with progress.

The draft stays waiting until the upload, the transcript job, and the
editorial job are all done. Empty job ids no longer count as done.
The transcript id comes from the draft move. The editorial id comes
from the episode detail. The screen follows both through the same job
stream the gallery card uses. A stopped pass reads failed, including
an interrupted pass that does not rerun. The gallery link is on the
screen the whole time. The episode link appears once the draft is
ready. The layout uses the episode page's type and the gallery's
progress bar.

The record mock spec no longer expects both full host tones. The
stored host stem is the greeting plus the lead before it. The
interrupted reply is absent.

## What surprised us

The host stem length is not a fixed count. One run here stored 100448
bytes and the next stored 100960. An earlier note had 98912. The lead
before the greeting moves with the audio clock. The spec now checks
that the stem is longer than one tone and shorter than two, and that
only one tone is loud. Putting the interrupted reply back would fail
that check.

A full reload would kill an upload that is still sending. The
processing screen therefore keeps the uploaders that are already
running. IndexedDB resume remains the path when nothing was handed
across.

`tools/check.sh` still stops before tests. Installed ffmpeg is 9.0.2
and the pin is 9.0.1. The gate was not changed.

Voice unit tests passed from `web/`. Ten files, 91 tests. The record
mock Playwright suite passed after the host stem assertion was
updated. Confirm, cancel, a tab close during the ask, and the
throttled upload were in that suite. The voice controller specs
passed as well. I did not open the page in a browser outside
Playwright, so I did not see a failed job on the screen itself. The
failed step text is pinned in the unit tests.
