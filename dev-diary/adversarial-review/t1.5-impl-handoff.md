## What exists now

`internal/settings/settings.go` holds one `Settings` struct with inline
model ids, the session cap, guest quotas, the daily spend ceiling, the
render concurrency, the data and media paths, and the public origin. It
holds a `Secrets` struct with exactly three references. `Load` resolves
the file named by `REPRISE_CONFIG`, falls back to
`config/reprise.local.toml`, and returns the settings with the loader
plan. Two sentinels separate the failures. `ErrSecret` wraps an
unresolvable secret. `ErrSettings` wraps a refused file.

`config/reprise.local.toml` points each secret at
`/home/nryn/work/reprise/.env` through an `env_file` source.
`config/reprise.box.toml` points each secret at `/etc/reprise/env`
through the same source. Both files hold inline values only. No value
appears in either file. `.env.example` lists the three variable names
with empty values.

`internal/settings/settings_test.go` reruns the test binary as a
startup helper. It proves a missing secret stops startup and names the
key, the source and the path. It proves a group-readable env file stops
startup and names the path. It captures `Plan.String` and probes the
full output for each dummy value. It proves the search fallback with no
`REPRISE_CONFIG` set. It proves each loader refusal surfaces through
`Load` by sentinel only.

## What surprised us

The loader refuses a group-readable env file by mode bits, not by
access. The check fires even for a privileged user. The failure arrives
as a resolution error that names the path and the mode.

A quoted env value fails as a resolution error, not as a parse error.
It maps to `ErrSecret` beside the missing secret case. An inline secret
and an unknown key fail as parse errors under `ErrSettings`.

A missing TOML file still stops startup. Each secret carries a required
tag, so an absent file fails with the key named and the source empty.

`go mod tidy` added the indirect TOML parser entry after the pin. The
build failed without it even though the direct requirement was exact.
