## Scrutiny notes (asked in the handoff)

(a) Cut order excluded from the hash is sound. `MergeRanges` sorts
before complementing, so order never changes the output. The unit pin
`TestHashInputsStableAcrossCutOrder` covers it.

(b) Cold open intersecting kept audio is correct. The spec removes each
accepted range from both stems and then places the cold open first. The
alternative (rendering the cold span verbatim) would return removed
material through the opening. The intersect keeps the episode playable
untouched.

(c) The e2e click pin derives its windows from `JoinTimes`, which shares
code with the assembly it measures. This circularity is contained, not
absent. Two independent anchors hold the positions: the unit pin asserts
an exact 3.0 s boundary for a fixed layout, and the e2e test asserts an
absolute ffprobe duration of 36.72 s within 0.2, which was re-derived by
hand from the word timings (6 s cut out, 11.95 s cold plus 0.75 s gap).
A separate check in `/tmp` spliced a real cut (removed middle) with hard
concat versus 10 ms acrossfade: deltas 0.2464 against material 0.0281
(ratio 8.76, fails the twice-material bar) versus 0.0282 (ratio 1.00,
passes). The threshold separates the defect class it targets.

(d) Resume recomputes, it does not go stale. `Resume` decodes only owner
and episode ids, then `Run` re-reads decisions, stems, and digests, so
changed inputs hash fresh. A cancel between the two blob persists and
the row write can leave orphan blobs, but they persist private and
grouped by episode, so the episode-scoped sweep still owns them. Noted,
not filed.

(e) The `audio/mp4` admission is wiring's job and fails closed: without
it the AAC persist errors and the run fails loudly. It is documented in
the `AACContentType` comment, the persist path, and twice in the
handoff. Loud enough.

(f) `RENDER_DEBUG_OUT` appears only in `render_test.go`, gated on the
env var, off by default. No production path references it. Verified by
grep (no non-test hits).

(g) Excluding render second 0 to 0.1 from every click window is a
legitimate exclusion. No splice exists at t=0 (the first range starts
playback), and the measured Opus priming click there is a codec edge,
not a cut. The first real join sits seconds later.

(h) The pins avoid the tone trap. The click pin runs on 440.0417 and
660.0417 Hz (non-integer, non-whole-second aligned) plus the steady
fixture stems. Integer-hertz tones appear only in tests that assert
hashes and rows, never clicks.

(i) `KindOf` registers exactly limit 1, idempotent, with `Resume`. This
matches the phase job-kinds table for `render`.
