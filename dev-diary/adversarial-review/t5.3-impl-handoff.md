## What it built

`internal/limits/` holds the guest caps, the spend view, and the kill switch.
The broker stays the single enforcement point. This package declares the
switch, answers the caps, reports spend, and serves the admin endpoints.

* `limits.go`: `SessionsPaused` aliases the broker kill switch declaration,
  so the admin switch and the mint check cannot name different flags.
  `CodeSessionsPaused` and `CodeGuestLimit` alias the broker refusal codes
  for the same reason. `Service` reads caps from settings (`GuestMaxSessions`,
  `SessionMaxSeconds`, `DailySpendCents`), flips the switch at once through
  the Keel flag store, and reports spend as ceiling minus headroom. The global
  figure reads both halves from the cost store. The per-owner figure reads the
  headroom from `KeyedBudget.Remaining` and subtracts it from the ceiling this
  service set through `SetLimit`, defaulting to the first-mint default the
  broker provisions. `CheckGuestSessions` names the quota refusal with the
  same code the broker answers. Twenty Go tests pin the pass side (a settled
  reservation moves the owner and global figures by exactly its price) and the
  refusal side (unknown owner, over-cap guest, denied config).
* `auth.go`: the `OwnerAuth` seam plus `StubOwnerAuth`, which denies every
  admin call with 403 `owner_required` until the owner login lands.
* `handler.go`: `GET /api/admin/limits` (caps, switch, global spend, optional
  per-owner figure via `?owner=`), `POST /api/admin/limits/pause` (immediate
  flip with read-back), `POST /api/admin/limits/owner` (per-owner ceiling
  edit). All refusals go through the shared error envelope.
* `web/src/routes/admin/`: the admin page behind the existing guest session
  path. It renders loading, owner sign-in needed, failed, and ready states,
  shows the switch with the same words guests see, today's spend with an
  explicit today-only note, the three caps, and a per-owner lookup. Twelve
  vitest cases pin the parsers, the refusal codes, and the formatting on
  fixed inputs.

## Owner login seam

The open login decision is still open, so no login was invented. The service
takes an `OwnerAuth` and every admin route sits behind it. `StubOwnerAuth`
denies all with `owner_required`, which the page renders as the sign-in state.
The real login plugs in as a new `OwnerAuth` that reads the resolved guest
session user and allows the owner. Swapping it touches no other file here.

## What surprised it

* The task text names the quota refusal `guest_limit`. The broker answers
  `guest_quota_reached` (`CodeQuota`). This change aliases the broker constant,
  so the wire keeps saying `guest_quota_reached`. If the product wants the
  shorter string, the broker owns the rename, not this package.
* `KeyedBudget` offers no per-owner ceiling getter, so the ceiling half of
  the per-owner figure is the value Reprise set: the admin edit when one
  exists, else the first-mint default. The global figure is pure Keel reads
  on both halves. The ledger carries no charge timestamps, so neither figure
  claims a history.
* Svelte component lint in this repo accepts no type syntax at all: no
  `import type`, no annotations, no generic `$state<T>`. Components import
  values only (an `emptyAdminSnapshot` value seeds the page state) and keep
  typed helpers in the co-located `.ts` module. A `let state` declaration
  also collides with the `$state` rune in the checker and must be renamed.

## Contract changes for consumers

* Main wiring (whoever owns `main` next): build the service from settings
  (`GuestMaxSessions`, `SessionMaxSeconds`, `DailySpendCents`), the shared
  flag store, `NewKeyedBudget` over the cost store, the cost store itself for
  the global figure, and `StubOwnerAuth`. `OwnerDefaultLimit` must equal the
  broker `OwnerSessionLimit`, or the per-owner figure disagrees with the
  ceiling the mint reserved against. Mount one handler per admin pattern
  behind the guest session middleware.
* The broker contract is unchanged. A flip here refuses the next mint with
  `sessions_paused` because both read the same flag name, pinned by
  `TestSwitchAndCodesMatchBroker`.
* The route table (`internal/api`) and its browser mirror do not list the
  three admin patterns yet. That file belongs to another scope. Whoever owns
  it should add `GET /api/admin/limits`, `POST /api/admin/limits/pause`,
  and `POST /api/admin/limits/owner` with stubs or this handler.
* Retention stays out. Nothing here deletes or expires. T5.4 owns that.
