# Implementer handoff

Takeover implementation. The first implementer left 16 uncommitted files and
no handoff. This round adopted that draft, verified it against the spec and
against the shipped Chaaya surface, fixed four defects, and committed twice.
Final hash: `eee9fb5bd105c76a73862cc3eaa40100f7b82395`. The tree is clean.
Only the owned paths changed. The full gate passes.

## What it built

`web/src/lib/voice/` holds the whole take. `socket.ts` runs the duplex loop.
It sends `session.update` with system prompt, greeting, keyterms and tools,
then routes `reply.audio`, `reply.done`, both transcript shapes, and
`session.ended`. `sendAudio` drops and counts blocks before the open and
after ending starts. `end()` sends `session.end` once across any number of
callers and resolves every waiter on `session.ended`. A call after the answer
already arrived resolves at once.

`take.ts` drains every block and keeps nothing. The user copy uploads at
capture rate and a resampled copy reaches the socket at 24 kHz. The host
copy uploads at the provider rate. Each `reply.done` flushes the player and
records the cut time with the interrupt flag as the mark in the host stem.

`session.ts` parses the broker session body field for field and throws on
any drift instead of opening a wrong socket. `pcm.ts` holds the pure audio
helpers with exact unit pins on synthetic samples. `record-state.ts` owns the
take controller. The page owns the `AudioContext` at the device rate and
passes it to the recorder and the stream player, so both stems share one
clock. The recorder runs with `autoStopSeconds: 0`, echo on, noise and gain
off, and `retain: false` with an `onChunk` that appends, sends, measures,
and returns. The end control arms on first press and ends on second. The
pagehide listener and destroy both funnel into the same once-only `end()`.
`SessionGuard` covers the HTTP close with its own latch.

`web/src/routes/record/+page.svelte` renders preflight, live, ending, and
recovery with native controls, accessible names, and keyboard support. The
mock flag swaps the provider and the upload server for doubles and feeds
generated input through the same drain. The resume flag rebuilds the server
from the durable client store and completes exactly the persisted bytes.

`web/src/routes/processing/+page.svelte` with `processing-state.ts` stays
with the finished take. It draws upload, transcription, editorial, and draft
from `JobStream` over the same job ids the gallery card will read. The mock
flag serves scripted SSE frames through the real follower.

`mock.ts` holds the doubles. `MockSocketHandle` answers the setup with
greeting audio, fires one reply after the counted input block, and answers
the close with the ended frame while logging every received type.
`MockUploadServer` answers the real chunk protocol from memory and adopts
persisted chunks after a reload.

## Proof

Seven unit files pin the pure layer and the loop. 47 vitest tests pass. Five
Playwright tests drive the mock take. Both uploaded stems pass `ffprobe` at
the right rates with every marker present in the user stem. Memory pins a
ratio under 4 from a one minute take to a twenty minute take through the
browser heap sampler. Reload completes over exactly the persisted bytes with
both receipts. Leaving sends `session.end` exactly once. Processing reaches
the draft through the shared follower. `./tools/check.sh` ends OK.

## What the takeover found and fixed

The draft was complete in shape and needed four fixes. First, the spec file
declared node modules inline, which fails the typecheck because the file is
a module and the declarations read as augmentations. A sibling ambient
`node-shims.d.ts` now carries them with no imports or exports.

Second, `end()` hung when called after `session.ended` already arrived. The
leaving test exposed it. Ending a take the page already closed never hung in
the draft because no test tried it. The socket now latches the answer and a
unit test pins a late `end()`.

Third, two spec locators were wrong. One matched two elements as a
substring. One used exact matching against a partial string. Both now match
the full rendered step text.

Fourth, the gate rejects store shaped calls, and that pattern matches
`Map.get` and param reads too. The existing tree avoids that shape
entirely. The voice path now uses plain records, a table driven base64
decoder, and entries based query reads. The decoder rewrite stays sample
exact through the round trip tests.

## Surprises

The gate scan is broader than its comment suggests. Any `.get(` call fails
it, including collection and query reads. Future web code should avoid that
shape from the start.

The upload route pattern is reserved server side but no handler exists in
this snapshot. The mock server therefore proves the client against the
library protocol, not against the real route. The client sends `audio/pcm`
bytes with the owner it knows.

The real take sends the episode id as the upload owner while the mock take
uses the default guest owner. No server contract settles which value the
open body should carry. The review should confirm the owner with whoever
wires the upload route.

Chaaya carries `encodeWav` and `LiveLevel` and this change uses neither. It
uses the library resampler, the library level math, and a native meter
instead. Nothing here rebuilds library work. Stems upload as raw PCM and
only the test harness wraps bytes as WAV for the measuring tool.

## Contract changes

The socket forwards the broker session config unchanged. The parser expects
`session_id`, `episode_id`, `token`, `expires_in_seconds`,
`max_session_duration_seconds`, and `config` with `system_prompt`,
`greeting`, and a string list of `keyterms`. Any broker drift fails loudly
at parse time.

The take POSTs `/api/sessions` to open and `/api/sessions/{id}/end` to
record the close. The guard beacons the same end URL. Both tolerate a
missing handler because the socket close already stops the billing clock.

The record page reads `?mock=1` and `?resume=1`. The processing page reads
`?episode`, `?transcript`, `?editorial`, `?uploads=done`, `?userBytes`,
`?hostBytes`, and `?mock=1`. The uploading client and the gallery card must
agree on the job ids the processing screen follows.

## Fixture status

No `testdata/sessions/` directory exists in this snapshot. Every check here
uses generated input with markers the tests find again, which satisfies the
audio testing rules with no microphone and no wall clock thresholds. When
recorded fixture sessions land, the mock script can replay them through the
same handle without touching the wiring.

No library issue arose. Chaaya `0.2.0` carried the recorder, the resampler,
the stream player, the uploader with its resume protocol, the guard, the
job follower, and the level math. The drain output matches the library
resampler sample for sample.
