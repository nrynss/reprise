Built the abandoned session sweep behind the live measurement the task
demands. The work owns `internal/broker/sweep.go`, `internal/broker/reconcile.go`,
`internal/assemblyai/terminate.go`, `internal/assemblyai/terminate_live_test.go`,
and the tests beside them only. The probe record keeps the raw responses.

## The three measured answers

Two live runs confirmed every answer on separate real sessions. Each run
connects about 40 seconds under a 120 second token cap.

1. DELETE does not end a connected session, and billing runs on. DELETE
returns 204 with an empty body. The socket sees nothing in the next 15
seconds, and the wire stays open. A later client `session.end` still draws
`session.ended` billing the full wall time (39.13 seconds against 41
seconds of wall on the second run, `audio_duration_seconds` null).
2. The record is gone after the delete. The session leaves the list, and a
fetch returns 404 `session_not_found`. It still reads 404 twenty seconds
later. A second DELETE returns the same 404. The duration is unreadable
afterwards, so the sweep settles before it deletes.
3. No other server side end exists. The Sessions API offers record fetch,
list, and delete only. The socket never sees `session.ended` unless the
client sends `session.end`. `expires_at` near one hour out stays unmeasured
as a close, because proving it costs a full hour.

Total live spend is about 10 cents across both runs, far under the 1
dollar budget.

## What it built

`internal/assemblyai/terminate.go` holds a `SessionsClient` over the
Sessions API. `FetchSession` returns status, close reason, a nullable
duration, start time, and artifacts. Open sessions decode with nil
duration and no artifacts. A missing record reports `ErrSessionGone`.
`TerminateSession` deletes the record and treats a 404 repeat as success
with `Deleted` false, because ending an ended session stays safe. Every
branch keys on status codes, never on provider wording.
`internal/assemblyai/terminate_test.go` pins the shapes against a fake
server, including the nil duration open shape and the idempotent delete.

`internal/broker/sweep.go` holds the `Sweeper` behind consumer declared
seams. One `Sweep` call lists candidates from a `SweepSource`, skips rows
younger than cap plus margin and rows the reconciler already settled, reads
each provider status, settles through `ReconcileAbandoned`, deletes the
provider record after, and writes the outcome on a `sweep_state` row the
file owns. A completed session settles its provider duration. A session
still open settles its elapsed time and raises a `sweep_open` alert beside
the over cap one, because the meter may run on. A record already gone
settles nothing and asks for review, the way an ambiguous resume settles
nothing. The kind is `sweep` with `Idempotent: true` and `MaxAttempts: 3`,
and `Resume` rebuilds the run from the progress snapshot.

`internal/broker/reconcile.go` grows three seams and no behavior change.
`Reconcile` now settles through an extracted `settleRead` that
`ReconcileAbandoned` reuses, so both paths share one claim guard, one money
path, one expired tail, and one alert once flag. `IsSettled` lets the sweep
skip settled rows. `AlertSweepOpen` names the still open settle. The full
existing suite passes untouched.

`internal/broker/sweep_test.go` pins the done criteria with real stores and
no network. A completed fixture at double the cap settles exactly once with
the shortfall on both ceilings and nothing held, and a second sweep changes
nothing: no second delete, no moved spend, no new alert. An open fixture
settles its elapsed time with both alerts. Young, settled, and gone
candidates move no money. Resume rebuilds the run, and the kind flags are
asserted.

The full gate passes in the worktree, including `go test -race`, the web
build, and the plan reference scan. The live probe passes twice.

## What surprised it

Deleting the provider record does not disturb a live socket. The call
continues and stays billable with no record behind it. That makes a false
positive sweep cheap in one direction (the talk survives) and costly in the
other (the books close while the meter runs, and the later duration is
gone). The sweep order, settle then delete, is load bearing for exactly
this reason.

The lease the broker opens expires at the token cap, so a production sweep
past cap plus margin always meets an expired lease. The fixture mirrors
this with a fake clock and proves the expired tail carries the sweep
settle. The open lease path stays covered by the reconciler suite.

The settings loader needs an absolute config path under `go test`,
because relative paths resolve against the package directory. The probe
record notes this beside the run command.

## Contract changes

Sweep listing waits on the store owner. `SweepSource.ListOpen` needs the
lease and reservation link on the session rows that T2.3 already flagged
as missing, plus a row age. Until that migration lands, the wiring passes
a source that carries the linkage, the way reconcile inputs carry it today.
No sweep can enumerate on its own before then.

Wiring should register the `sweep` kind from `Sweeper.Kind` under
`SweepKindName` and run it on a period shorter than the margin, with a
`SessionsClient` behind the `StatusReader` and `SessionEnder` seams. The
record delete is hygiene and audit, not a stop. The browser timer in T2.7
is the only stop, and the minted cap is the per session loss ceiling only
while the client ends on time. A truly abandoned session bills until the
provider outer bound, whatever that proves to be.

Provider adapter note. The reconciler seam still assumes a flat session
body with `duration_seconds`, `recording_url`, and `timeline_url`. The live
records show the real fetch shape: `status`, a nullable `duration_seconds`,
and an `artifacts` array. Whoever implements the reconciler reader should
decode the real shape from `SessionStatus` and resolve recording and
timeline URLs from the artifact types, not add a second flat client.

Stale comment outside owns. `internal/assemblyai/token.go` says the
provider ends the session at the cap even when the browser vanishes. The
T0.2 probe and this measurement both prove it does not. The file is outside
this task, so this change leaves it alone and records it here for the
reviewer.

No library issue arose. Keel `v0.3.0` carried the settle that always books,
the expired lease tail, and the job resume this work stands on.
