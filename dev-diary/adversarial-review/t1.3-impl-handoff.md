## What it built

`internal/api/routes.go` holds the route table as data and mounts it. All
thirteen routes exist as stubs. Each stub refuses with code
`not_implemented` through `wire.WriteError` at status 501. The upload
prefix, the job events route and the media route stay stubs. The real
upload mount, the broker stream and the blob store land with their own
changes, since each needs stores this change does not take.

`web/src/lib/api/types.ts` mirrors the table by hand. It reuses the shared
envelope types from Chaaya and adds no envelope code. `isNotImplemented`
lets screens branch on the stub code.

Two golden files bind the sides. The server test writes them under
`web/src/lib/api/testdata/`. The browser test decodes them. The refusal
golden parses through `parseErrorEnvelope` with code `not_implemented`.

## What surprised us

Nothing. Keel `wire` and Chaaya `wire` agreed exactly. The envelope bytes
the server writes parse on the first run.

## Contract changes later handlers need

`Register` takes only a mux today. Real handlers will need settings, the
stream broker, the upload handler and the media store. The change that
adds the first real handler should widen the signature then. `main` does
not mount these routes yet, since that file belongs to another change.
