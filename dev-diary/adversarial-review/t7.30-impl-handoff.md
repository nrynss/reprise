## What I built

### Privacy hook (`cmd/reprise/privacy.go`)

- The kinds hook builds the owner facing erasure service and the
  retention service over the shared database, media store, and
  provider key. It returns the erasure kind and the sweep kind, so a
  restart resumes both. Bare wiring registers nothing, so hook tests
  call every hook without stores.
- The mount hook binds the runner to both services, mounts publish,
  revoke, and erase behind the gate and the guest middleware, and
  mounts share metadata and share cover behind the gate with no
  session. Ownership checks read the request user the middleware set,
  so a signed-out visitor owns nothing and reads only published
  shares. The hook starts the retention sweep once at boot and daily
  after, on the boot context.
- One holder shares both service instances between the two hooks, so
  the kinds the runner holds and the routes the mux holds serve one
  state. Tests reset the holder after each case.

### Dropped core stubs (`internal/api/routes.go`)

- The route table still lists the publish and erase patterns, so the
  goldens and the browser mirror match the served surface. `Mount`
  leaves those three patterns unregistered instead of stubbing them,
  so the privacy hook mounts them with no duplicate panic.
- `TestMountKeepsStubsForUnmountedRoutes` became
  `TestMountLeavesPrivacyPatternsForTheFeatureHook`. It pins 404 on
  the publish paths and mux 405 on the erase path, with the chain
  untouched.

### Keep moves covers and resolutions (`internal/retention/keep.go`)

- `Keep` repoints the cover row and the resolution links at the
  keeper in the same transaction. Links follow their commitment
  mentions, so a link survives even when its evidence lives on
  another episode. Both moves skip a missing table, because the cover
  and memory passes may never have run. The rendered source link
  names no owner and keys on the unchanged episode id, so it needs no
  move. A new test pins all three rows plus the guest delete that
  failed on a foreign key before.

### Episode controller (`web/src/routes/threads/threads.ts`)

- Fixture publish keeps its exact flag flip and wording, with no
  fetch. Live publish posts the publish route and shows the real
  share path, and live revoke deletes it and shows the revoked state.
  A refused publish leaves the episode private with a retry line.
- Erase names the erasure job id the route started when the answer
  carries one, and keeps its standing lines otherwise. Refusal text
  is byte identical, so the existing proofs still pass.
- Five new unit cases pin the parsers, the fixture flip with no
  fetch, the live publish plus revoke call order, the named erasure
  job, and the refused publish.

### Binary level proofs (`cmd/reprise/privacy_test.go`)

- `TestPrivacyKindsRegisterEraseAndSweep` pins both kind names and
  the duplicate refusal.
- `TestPrivacyShareOpensAndRevokes` mounts core routes first, then
  the hook, so a regressed stub panics instead of hiding. A caller
  with no cookie reads the published metadata and cover, a stranger
  reads 404 on owner routes, and revoke turns both share routes 404.
- `TestPrivacyEraseRemovesEveryCopy` erases through the mounted
  route and finds no row, no media row, no media file, no cover
  file, and deleted provider copies.
- `TestPrivacySweepExpiresTheIdleGuest` publishes, ages the guest,
  sweeps, and finds no episode, no user, and a 404 share, with
  deleted provider copies.

## What surprised me

- `Mount` mounting the stubs first was the only panic source. The
  table itself could stay, which kept the goldens and the browser
  mirror green with no edits outside owned paths.
- A `DELETE` on the episode path answers 405 from the mux itself
  once core mounting owns sibling methods there. The test pins that
  shape.
- `rendered_sources` carries no owner column, so `Keep` moves
  nothing for it. The foreign key failure came only from `covers`
  and `resolutions` still naming the guest.
- The `TestFeatureHooksAreWired` case calls every mount hook with a
  bare mux, so `mountPrivacy` returns early on incomplete wiring
  instead of refusing the boot.
- ESLint rejects a useless assignment in a catch block, so the
  revoke flag declares without a value first.
