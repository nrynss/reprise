## What exists now

- `internal/episode/playback.go`: `EditWords`, `StemMediaID`, and `RenderMediaID` on
  `episode.Service`. `EditWords` reads `words` where `source = 'edit'`, ordered by start time, and
  converts stored milliseconds to seconds. `StemMediaID` reads `stems` and prefers the user role
  over the host role. `RenderMediaID` reads the newest row in `renders` by `rowid`. All three check
  `Get` first, so an unknown or foreign episode reports `ErrNotFound` before any further query runs.
- `internal/api/episodes.go`: the detail handler now calls all three and adds `words`,
  `audio_url`, and `render_audio_url` to the wire body. Both addresses go through the existing
  `mediaPath` helper, which builds `/media/{id}`, the already owner-checked route. No new route
  opens.
- `web/src/lib/editor/draft.ts`: `loadFromBackend` reads the same detail shape the episode view
  reads (words, proposals, `audio_url`) instead of a shape the endpoint never sent. It plays the
  stem address, not the render address, because the editor works the raw take. An episode with
  stored proposals but zero words still loads as an empty live draft with a notice, rather than
  falling back to the scripted fixture. The fixture fallback now fires only when the request itself
  fails.
- `web/src/routes/threads/threads.ts`: `EpisodeController.mountLive` now loads the render address
  into the player and computes duration from the last stored word's end, so playback controls
  appear only once a render exists. `seasonHref` is the single place that decides where a gallery
  row links. A draft opens the editor, with the fixture query kept for fixture drafts, and every
  other row keeps opening the episode. `draftEditHref` gives the episode page an editor link
  whenever the live episode is a draft, independent of whether a render exists yet, so playback
  waiting never removes the way in.
- `web/src/routes/+page.svelte` and `web/src/routes/episode/[id]/+page.svelte`: wired to
  `seasonHref` and `draftEditHref`. The episode page already had the "playback waits" copy for a
  live episode with no audio address, so it needed only the new edit link, not new copy.

## What surprised me

- The draft I inherited was already complete and correct against the schema (`words`, `stems`,
  `renders` in `internal/store/migrations/0001_schema.sql`) and against the task's three bullets. I
  found no defect worth fixing beyond finishing the commit. I re-verified the SQL column names, the
  `transcript.SourceEdit`/`RoleUser`/`RoleHost` constants, and the existing `/media/{id}` owner
  check by hand rather than trusting the draft's own comments.
- The editor plays the stem, and the episode page plays the render. That split is deliberate, not an
  oversight: the editor works the raw take the proposals were cut against, while the episode page is
  what a finished listen plays.
