## What was built

The binary now serves an export bundle for a ready episode the owner
holds. `GET /api/episodes/{id}/export` answers one zip with six files
in fixed order. Audio carries the AAC render unchanged. Video carries
a 1920 by 1080 waveform build over the cover still. Captions carry SRT
and WebVTT grouped from the rendered words. Cover carries the stored
square PNG. Description carries the show notes with timestamped
chapter lines.

`internal/export/service.go` holds the owner scoped reads and the
route. Every query names the owner beside the episode. Lookup finds
the owner first, then the ownership check runs, so a stranger reads
the same 404 as a missing episode. Any other state reads 409 with the
`export_not_ready` code. The download carries `no-store` and an
attachment name per episode number. `internal/export/bundle.go` holds
the zip assembly over a temp directory that is removed before return.

`cmd/reprise/export.go` follows the privacy hook shape. The kinds hook
builds the service and registers the `export` kind with a limit and no
resume work. The mount hook serves the route behind the gate and the
guest middleware. Bare wiring registers and mounts nothing. The
existing merge refuses a duplicate kind name, and a test pins that.

The episode page shows an export control on live ready episodes. The
control downloads the bundle through `exportBundle` in
`web/src/routes/threads/threads.ts` and names each refusal status on
its own line. Fixture mode keeps its standing notice.

## What surprised us

The runes-only scan matches any `.get(` call, including
`headers.get(`. The filename helper reads headers by iteration
instead, with a comment that states why. Staticcheck reads a struct
literal conversion as a simplification, so chapters convert with an
explicit conversion. Seeded copies share catalog blob bytes while
rows stay per owner, so every export query scopes both columns. The
`ffmpeg.Duration` helper from the media library probes the render in
place, and no new probe code was needed.

## Contract changes needed

None outside the owned paths. The route is new surface, not a change.
The zip layout lives in `BundleOrder` with one name per file. The
refusal codes are `not_found`, `export_not_ready`, `internal`, and
`method_not_allowed`. The core route table still lists no export
pattern, so no mount clash exists. The registered kind runs inline in
the request and declares no resume work. A later async endpoint can
schedule that kind without a new hook.
