## What it built

The controller builds `SessionCap` beside the socket when the take goes
live. It passes the take end path as `finish` and the broker
`max_session_duration_seconds` as the cap. The end path is the armed control
itself, so the timer ends rather than arms and the socket latch below it
keeps every close path to one close message.

`stop` runs on every take end path. That is the take end itself, the destroy
path and the pagehide path. The controller calls `wake` on show and on every
visibility change. The snapshot carries `capWarning` and `capText`. The page
renders the text in a `role="alert"` region while the warning holds, beside
an `End session now` button that runs the same end control. The standing end
button stays enabled and focusable through the warning.

Under the mock flag the cap runs on a harness clock the run moves by hand.
The harness exposes advance, jump, wake and a warning reading. Production
uses the system clock. No check waits on a real duration.

## Proof

Two Playwright proofs drive the mock take. The first advances the harness
clock to one second past the warn point, sees the live region announce 60
seconds with both end controls reachable, then advances past the cap and
sees exactly one `session.end` with nobody pressing end. The take lands on
the processing screen. The second jumps past the cap with no timer running,
sees zero close messages, dispatches a visibility change and sees exactly
one `session.end` followed by the same landing. A mutation probe removed the
cap start, rebuilt and saw both proofs fail. The pins are load-bearing. The
five older mock proofs still pass unchanged.

## What surprised it

The lint setup parses no type syntax inside `.svelte` files. A typed event
parameter and a typed `$state` declaration both failed the parse. The page
now carries no annotations at all. The warning button handler is an inline
arrow with contextual typing, and its cleanup runs through an
`AbortController`. Future page work should infer every type from usage.

The mock Playwright config serves the built site, not the source tree. A
mutation probe means nothing until `npm run build` runs first. The probe
above rebuilt before rerunning.
