## What it built

`SessionCap` runs the browser side stop for one minted session. The page
starts it beside the socket at `session_max_seconds` and passes the end
control path in as `finish`, so the timer ends through the socket `end`
latch instead of owning a second close mechanism. At the warn point it fires
`onWarn` once with whole seconds left and exposes `warnText` for the live
region, so the screen announces the end before it arrives. `stop` cancels the
timer when the take ends any other way, so the timer never closes an already
closed take.

Time comes through an injected `CapClock`. Every tick compares the clock
reading against the deadline instead of counting ticks. A jump from sleep or
a suspended tab therefore ends on the next evaluation rather than waiting out
stale delay. `wake` re-reads the clock at once for pages that call it on show
or visibility change. A late timer firing on its own takes the same branch,
so both wake styles end immediately.

## Proof

Six vitest proofs run on a fake clock the test moves by hand. Short caps
stand in for the minted cap. No proof waits on a real duration. The mock
socket answers the close message, so two proofs run the full close path
through the real `VoiceSocket`: past the cap the log holds `session.update`
then exactly one `session.end`, the ended frame arrives once, and a further
advance changes nothing. A second pair covers the suspended page: a jump with
no timer running ends on `wake`, and a jump followed by a late timer fire
ends at once. Both leave no timer pending. The last two pin the warn order
with seconds left and the silence after `stop`, plus rejection of caps that
could never bound a session.

## What surprised it

The first run of the wake proof failed and exposed a real defect. `tick`
nulled the timer field without cancelling the pending handle, so the stale
timeout survived the jump. The fix clears the handle at the top of `tick`.
Clearing an already fired timeout is a safe no operation in both clocks. The
proof now pins zero pending timers after each jump path.

## Contract changes

The page wires three calls. It builds `SessionCap` with the end control path
and the broker `max_session_duration_seconds`, calls `start` when the take
goes live, and calls `stop` wherever the take ends otherwise. It should call
`wake` on show and visibility change and render `warnText` in a live region
with keyboard reachable controls when `warning` turns true. The socket needed
nothing new. Its latched `end` already gives the once-only close the timer
calls into. No library issue arose. No workaround was taken.
