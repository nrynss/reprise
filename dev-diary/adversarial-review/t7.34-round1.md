## Where cut ids come from

- Live cut ids come from stored proposal rows (`readStoredDraft`, `textOf(item, 'id')`). The server
  mints them with keel `id.New()`, which yields 32 lowercase hex characters. A stored id never equals
  a prototype key in production.
- `refreshCuts` calls `proposalIdForCut` only with ids from `editor.cuts`. In a live draft every one
  of those is an own key of the record, so the cut cards read correctly.
- `revertCut(cutId)` is public and takes any string. The edit page passes `card.id`, which is always
  backed. A caller or test that passes an unbacked id lands on the prototype.
