# T2.2 implementer handoff

## What it built

New package `internal/host` with one read path and one pure builder. `Load`
reads the owner's oldest unused callback, recent mentions, and episode numbers
from SQLite, then `Build` renders the session config. The greeting cites the
planted callback with its source episode in one sentence. A season with no
callback gets a warm first-episode opener. The system prompt carries the host
voice, the interrupt to follow up, one question at a time, up to three recent
threads with quotes, and a closing rule that binds the model to the listed
rows. Keyterms rank distinct excerpts by count, then by recency, capped at one
hundred. Seven tests seed a four episode season and pin the golden greeting,
the keyterm order, the thread cap, owner isolation, and the used flag.

## What surprised it

The mentions table holds kind, word offset, and quote, but no name column. The
quote text doubles as the keyterm surface, and dedupe folds case variants with
the most recent wording winning. The fixed prompt wording holds no digits and
no proper names, so the provenance test stays exact. The callbacks row points
at an episode and a mention, and the two can disagree. The greeting cites the
mention's episode, because that is the episode the words came from.

## Contract changes

The broker calls `host.Load(ctx, db.Reader(), ownerID)` and embeds the result
in the session response. `Config` marshals as `greeting`, `system_prompt`, and
`keyterms`, which match the provider session update names, so the socket layer
forwards them unchanged. `Load` only reads. Nothing here marks the callback
used. The broker or the callback selection change should own that write, after
the host speaks the greeting. The word offset never reaches spoken text. It
stays available for thread links. If a later change adds a normalized name
column to mentions, keyterms should switch to it.
