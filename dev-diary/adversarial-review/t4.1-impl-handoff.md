## What it built

`internal/memory/` holds the cross episode index. Seven files.

* `memory.go`. Package doc, four sentinels, and the two ranking
  constants. Keyterms cap at one hundred. A topic circles at three
  episodes.
* `normalize.go`. `NormalizeName` lowercases, trims edge punctuation
  and space, and collapses inner gaps. `QuoteInWords` and
  `QuoteOffset` match a quote as one contiguous token run, so casing
  and commas never decide. A blank quote never matches.
* `threads.go`. `RecurringNames` groups entity mentions by normalised
  quote and keeps groups in two or more episodes, oldest first.
  Key phrases, commitments, and doing mentions never qualify.
  `CircledTopics` keeps key phrase groups in three or more episodes
  with no close on record. `Keyterms` ranks every distinct name by
  mention count, then by newest episode, with the latest wording
  winning. `CountMentions` returns mention and episode counts with
  first and last episode numbers, so spoken counts repeat queries.
* `commitments.go`. The `Model` seam with two calls, one for marking
  and one for judging. Strict JSON parsing for both answers.
  `MarkEpisode` reserves budget first, persists the raw answer,
  rejects candidates whose quote misses the words, and stores the
  verified ones as `commitment` mentions with their offsets. A rerun
  replaces instead of doubling. `ResolveEpisode` closes one
  commitment against one later episode and fails when the evidence
  quote misses the later words. `Estimate` prices calls from catalog
  rates the wiring passes in, so no price lives in code.
* `resolutions.go`. `Migrate` applies the memory namespace beside the
  diary tables. `StoreResolution` writes the evidence as a `doing`
  mention and links it to the commitment. A second close replaces
  the first.
* `migrations/0001_memory.sql`. The `resolutions` table with
  cascading keys to mentions. Deleting an episode removes its
  resolutions.
* `memory_test.go`. A seeded four episode season built in the test.
  The planted threads mirror the demo beats. Maya recurs in three
  episodes under two casings. Lisbon recurs in two, once dotted.
  The allotment phrase spans three episodes, so it circles.

## Pins, all offline

* The marking test stores the exact quote with offset one and
  rejects the drifting quote, then reruns to pin replace semantics.
* The resolution tests close with evidence, reject missing evidence
  with `ErrModel` and no rows, and store nothing on a negative
  answer while still settling.
* Refusal returns before any model call. Missing words fail with
  `ErrNoWords` before any model call.
* Strict decoding rejects an unknown field and garbage text.
* A hand run mutation flipped the token comparison and the marking
  test failed with both candidates accepted, so the pin holds.
* Episode deletion cascades to zero resolution rows. Migration runs
  twice with no change.

## What surprised it

* The mentions table carries no name column, so grouping reads the
  quote. The host package already treats quotes this way. The index
  follows it and folds case variants with the latest wording shown.
* Commitments and doing mentions live as mention kinds, following
  the host seed data. Only the link between them needs a new table.
  The callbacks table set the precedent for a linking row.
* Episodes carry no timestamps, so counts speak in episodes and
  mentions, never in days. A phrase like three times in 34 days
  must come from a later column or stay phrased in episodes.

## Contract changes

### Provider side method to add

`Model` needs a production binding. The provider package should add
two text calls on its client, following the editorial method shape.
One takes the commitment transcript and returns raw JSON shaped as
`{"commitments": [{"quote": "...", "text": "..."}]}`. One takes the
commitment plus the later transcript and returns raw JSON shaped as
`{"done": true or false, "quote": "..."}`. The prompt builders
`CommitmentPrompt` and `ResolutionPrompt` live here, so the provider
side sends the given text unchanged. No audio travels. The model id
and the token rates arrive from settings through the caller.

### Wiring notes

* Call `memory.Migrate` beside the store opener at boot. Call the
  marking run after the analysis pass stores an episode mentions.
  An analysis rerun wipes that episode mentions, so replant its
  commitments after every retry.
* Fill `MarkConfig` and `ResolveConfig` with the diary writer, the
  model binding, a cost budget, catalog rates, the model id, and a
  receipt sink pointed at the episode media area. Both runs reserve
  before the call and settle the estimate after.
* Register a memory job only if the scheduler wants one. The package
  stays safe under explicit retry, because stores replace and model
  calls never repeat inside one run.

### For callback consumers

* Read open commitments oldest first from `OpenCommitments`. Read
  closed ones with their evidence from `ResolvedCommitments`.
* Read recurring people and places from `RecurringNames` with a
  minimum of two episodes. Read circled topics from
  `CircledTopics`. Every hit carries its episode number, quote, and
  word offset for thread links.
* Read the transcription boost from `Keyterms`. It ranks by count,
  then by recency, capped at one hundred.
* Read spoken arithmetic from `CountMentions`. It answers zeros for
  unknown names, because absence is an answer.

### For erase consumers

Episode deletion already cascades to mentions and resolutions
through foreign keys. The erase target list should still name the
`resolutions` table beside mentions, so a future row without a
parent episode cannot linger.
