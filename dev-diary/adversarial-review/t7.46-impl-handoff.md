## What was built

`wordJSON` gains `Speaker string` tagged `json:"speaker"` with no
`omitempty`, and `wordsOf` forwards `EditWord.Speaker` into it. The
detail endpoint now sends the stored speaker on both `words` and
`render_words`. Host words read as `host`, guest words as `user`, and
older rows with no speaker serialize as `"speaker":""`, which the
existing editor mapping already reads as unknown rather than the guest.

## Surprises

No omitempty was the load-bearing choice. The editor maps a missing
key and an empty string to the same unknown label, so behavior matches
either way, but always serializing keeps the key present for legacy
rows and makes a dropped field detectable on the wire.
