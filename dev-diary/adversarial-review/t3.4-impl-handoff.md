# T3.4 implementation handoff

Commit `2a3cb57` on `task/t3.4` in worktree `t3.4-impl`. It owns
`internal/render/` only. The full gate passes in that worktree, including
`go test -race`, staticcheck, and every web check through playwright.
Pinned ffmpeg and ffprobe 9.0.1 ran every audio pin.

## What it built

`internal/render/` holds the edit model and the job, not a renderer.
Seven files, all new.

* `render.go`. Targets (-16 LUFS integrated, -1 dBTP, range 7),
  constants (10 ms crossfade, 750 ms cold open gap, 48 kHz mix),
  sentinels, the `Media` seam, and `StoreMedia`, which binds a media
  store to its index behind one interface.
* `edit.go`. Pure edit model. Word offsets become millisecond ranges.
  Cuts merge, kept ranges complement them, the cold open intersects the
  kept audio so removed material never returns through the opening.
  `HashInputs` names the render from stem digests, offsets, cuts, cold
  open, duration, and targets. Cut order never changes the hash.
* `audio.go`. Two stages over `keel/ffmpeg`. Mix first: both stems to
  one 48 kHz stereo file with alignment offsets applied. Assemble next:
  one graph trims kept ranges with 10 ms acrossfades, splices cold open,
  gap, and episode, then normalises in two passes. `JoinTimes` exposes
  every join position for probes.
* `store.go`. Readers for accepted cuts, cold open, and render rows.
  A cut counts while its latest decision reads accepted, so a revert
  drops it. Dangling spans drop. Words come through `transcript.Load`,
  so the render and the editor read one order.
* `run.go`. The resolver. It reuses the stored output when the hash
  matches and both blobs still read. Otherwise it mixes, measures,
  encodes Opus plus AAC in one run, verifies loudness on the bytes,
  persists both blobs private grouped by episode, and writes the
  `renders` row. `KindOf` registers limit 1, idempotent, with `Resume`
  rebuilding from the descriptor the first attempt published.

## Pins, all measured on bytes

* `ebur128` reads -16 LUFS within 1 on generated tones and on the
  steady fixture stems. The pin parses the filter summary itself.
* The click pin decodes the Opus output and compares sample deltas at
  every planned join against the rest of the same render. It also
  checks window peaks, which a fade can never raise.
* Double render reuses hash and blob ids. Resume from an interrupted
  record reaches the same hash. Cancelled context stores no row.
  Full cuts fail with `ErrEmpty`. A reverted cut renders nothing away.
* The concat mutation (fades forced to zero) fails the unit pin and
  the tone pin with 0.199 against twice 0.040. The pin is load-bearing.

## What surprised it

`keel/edl` renders one input at fixed range 7 and peak -2. The episode
needs a two stem mix, a duplicated cold open, and peak -1. The graph
here is product assembly over `keel/ffmpeg`, not library work rebuilt.
No library issue follows, so none was filed.

Test tones need care. Integer hertz tones cut at whole seconds hide
clicks by phase alignment. Mixed steps can cancel across stems. Opus
padding clicks at second zero, so edges stay out of every window. The
probe derives join positions from the same decision rows the run read.
Guessed positions missed by 50 ms and once hid a real spike.

The store wiring must admit `audio/mp4`, because the default media
type set carries no MP4 audio. Tests open their store with it added.

## Contract changes

For analysis. Read the `renders` row by episode and input hash. It
carries `opus_media_id`, `aac_media_id`, and measured loudness.
Resolve bytes through mediastore `Get` on either id. The job terminal
data carries the same shape as JSON. This task moves no episode state.
Wiring owns that.

For export. Take `aac_media_id` as the upload master and
`opus_media_id` for streaming. Probe durations with ffprobe. Keep
`audio/mp4` in the store content types or AAC persistence fails.

`RENDER_DEBUG_OUT` in the tests saves a render copy for manual
probing. No memory server answered from this session, so no graph
recall or write ran. This file carries the full context.
