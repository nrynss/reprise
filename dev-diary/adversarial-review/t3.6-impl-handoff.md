## What it built

`internal/cover/` draws one square image per episode from the stored title and show notes. `Run` reserves budget first and refuses before any model call. It briefs the model through `Prompt`, which names the episode subject and refuses faces, people, animals, and all lettering. `Validate` screens the answer for decodable PNG bytes, a square frame, a sane edge, and real color variation. A failed call or rejected art stores the deterministic fallback instead. The fallback draws a 1024 square from the episode number with a hue gradient and a centered bitmap numeral, so it needs no model and no money. `Kind` sets limit 1 with no idempotence and no resume path. `ScriptedModel` stands in for the image endpoint offline and records the request it heard.

## Model reachability offline versus live

No image endpoint was reachable from this worktree, and no key was used. Every test runs offline through `ScriptedModel`. The `Model` interface is the seam the production wiring binds later. It takes the brief plus title, notes, and episode number, and returns PNG bytes.

The live binding needs one small addition outside this task. `internal/gemini` owns all provider calls, so the image call belongs there as a new method that requests image output through the existing Vertex client. This package already consumes that shape through its `Model` interface, so the wiring needs only a one line adapter. No code here will change when that method lands.

## Fallback proof

`TestRunFallsBackOnModelFailure` forces a model error and asserts the stored row carries the fallback mark at 1024 square with a valid file. `TestRunFallsBackOnRejectedArt` repeats the proof for undecodable bytes, a rectangle, and a flat panel. `TestFallbackDeterministic` asserts one number draws identical bytes twice and two numbers draw different panels. `TestEveryEpisodeGetsSquareCover` draws three seeded episodes and counts three square covers.

## Contract changes for export

The wiring should register `cover.Kind` under the `cover` name and call `cover.Run` with a `Config` carrying the diary writer, the image model, a cost budget, the model id from settings, owner and episode ids, a cover directory, and a receipt sink. The run keeps its own `covers` table beside the diary tables with guarded statements, so no migration step is needed. Each row holds the file name, the SHA256 of the bytes, the pixel size, and the fallback mark for its episode. Files land as `<episode-id>.png` inside the cover directory. Export reads the file through the `covers` row for the episode. A rerun overwrites the same file and replaces the row, so repeated calls stay safe. The brief reads the `title` and `show_notes` proposal rows the editorial pass stored, plus the episode number from `episodes`.
