## Findings

### F1 — Severity M — `testdata/sessions/steady/user-a.wav:1` (+ 5 siblings)
- **What:** All six committed user wavs carry corrupt RIFF headers: `RIFF size 2147479588`, `data size 2147479552`, against real file sizes 105268–150548 bytes. `ffprobe` warns `Packet corrupt … Estimating duration from bitrate` on every wav; Python `wave` reports `nframes 1073739776` (duration ~48696 s) while only ~105–150 KB of frames actually read. Same defect class T0.6 records for `testdata/speech/`. Audio bytes are intact (ffprobe's estimated durations match the README), so measurements survive with a workaround — but any strict header-trusting reader gets a wrong duration, and the phase bar is `ffprobe` with no warning.
- **Pin (fails today):** `ffprobe -hide_banner steady/user-a.wav` → emits `Packet corrupt` + `Estimating duration from bitrate`; `python3 -c "import wave; w=wave.open('steady/user-a.wav'); print(w.getnframes(), w.getnframes()/w.getframerate())"` → `1073739776 48695.68` instead of ~2.79 s. Repeats on `steady/user-b.wav`, `pauses/user-a.wav`, `pauses/user-b.wav`, `bargein/user-trigger.wav`, `bargein/user-bargein.wav`.
- **Mutation:** regenerate the stems with `espeak-ng … --stdout > user-a.wav` (unseekable stdout, sizes never patched) instead of `espeak-ng … -w user-a.wav` (seekable, sizes patched). One-line change in the generation step reintroduces the exact header values.

### F2 — Severity M — `testdata/sessions/recreate.sh:10` (`IMG="${TTS_IMAGE:-ubuntu:24.04}"`), `:18` (`apt-get install -qy espeak-ng`)
- **What:** Toolchain is unpinned while `README.md:75` claims "the pinned Docker image". Moving `ubuntu:24.04` tag plus unversioned `espeak-ng` cannot reproduce bytes; the README's `espeak-ng 1.51` claim is unverifiable from the script. Same pinning bar T0.6 states (image digest and/or package version, named).
- **Pin (fails today):** `grep -nE 'ubuntu:24.04|apt-get install -qy espeak-ng$' testdata/sessions/recreate.sh` returns both lines with no `@sha256:` digest and no `=version`; `grep -c 'sha256:' testdata/sessions/recreate.sh` → `0`.
- **Mutation:** replace `ubuntu:24.04@sha256:<digest>` with `ubuntu:24.04` and `apt-get install -qy espeak-ng=1.51*` with `apt-get install -qy espeak-ng`. Dropping either pin reintroduces the defect in one line.

### F3 — Severity M — `testdata/sessions/recreate.sh:19-29`
- **What:** The script cannot recreate the committed fixtures. It writes six `.raw` clips (`--stdout` stream dumps) and stops at `echo` instructions for manual live streaming. Nothing maps `.raw` → committed `user-*.wav`, and nothing writes `events.json`/`timeline.json`/`metadata.json`/`recording.ogg`. The T0.5 spec asks for "the command that recreates it"; this is half a command plus prose. The `--stdout` path is also the suspected source of F1's corrupt headers (cf. T0.6 cause).
- **Pin (fails today):** `grep -cE 'events\.json|timeline\.json|metadata\.json|recording\.ogg|user-.*\.wav' testdata/sessions/recreate.sh` → `0` write sites (only the `echo` text mentions them generically); executing the Docker block would leave `steady/`, `pauses/`, `bargein/` untouched.
- **Mutation:** delete the `.raw`→`.wav` conversion plus the scripted stream-and-store block, leaving only the current `echo` tail. That deletion is exactly the present state.

### F4 — Severity L — `testdata/sessions/README.md:19-22` ("cuts into the reply 2.5 seconds after the story audio starts")
- **What:** Wrong number. Story-turn first `reply.audio` lands at 7.34 s, barge `input.speech.started` at 12.72 s: delta **5.37 s**, not 2.5 s. The interruption itself is real (story `interrupted`, barge `completed`), so only the doc value misleads.
- **Pin (fails today):** `python3` over `bargein/events.json`: first `reply.audio` with `reply_id=resp_9e78…` at 7.34 s vs second `input.speech.started` at 12.72 s → `12.72 − 7.34 = 5.37 ≠ 2.5`.
- **Mutation:** change the corrected `~5.4 seconds` back to `2.5 seconds` on that line. Single-number edit reintroduces the false claim.
