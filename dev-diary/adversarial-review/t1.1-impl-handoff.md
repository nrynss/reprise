## What surprised me

Keel sqlite Migrate takes a context, a database, a namespace, and a file system.
It reads files at the file system root in filename order and skips recorded files.
It runs each file plus its ledger row in one transaction and forbids BEGIN and COMMIT inside files.
The ledger table name is the namespace plus _schema_migrations, so mine is reprise_schema_migrations.
Open enables foreign keys on every connection through the DSN and uses WAL mode.
The writer pool holds one connection and reader connections carry query_only.
Keel stores use namespaces job, cost, mediastore, lease, and flag.
The specification names job, media, upload, and cost, so two details differ.
The media namespace reads mediastore in code and upload holds no migrations at all.
Lease and flag also keep namespaces in the same file though the table omits them.
Table names are jobs, cost_charge, cost_budget, cost_reservation, cost_owner_budget, media, lease_entry, and flag_value.
None collides with diary tables.
Keel sqlite imports the driver itself, so my package resolves the driver name through the keel import.
New code imports only keel sqlite, which the module already requires, so go.mod and go.sum stay byte identical.
Proof runs happened in a scratch copy under /tmp with the module path rewritten, plus gofmt and vet probes.
I left the worktree gate for the reviewer and ran no further toolchains after the proof.
