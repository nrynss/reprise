## What it built

`internal/episode/lifecycle.go` guards every episode move with one conditional SQL update. `Begin` inserts a private episode in `recording` and mints its share token through `keel/id`. `Transition` enforces the allowed pair table and reports a stale current state as illegal. Named helpers cover each trigger. `MarkDone` is the only path into `rendering`. `Fail` accepts any state. `Retry` returns a failed episode only to a working state. `MarkInterrupted` moves working states to `failed` after a restart and treats a late interrupt on `failed` as harmless. `Current` reads the stored state.

`internal/episode/lifecycle_test.go` pins the contract. A table test tries all 36 state pairs and allows only the listed moves. A concurrency test fires two `MarkDone` calls at once and requires exactly one winner. Further tests walk the happy path, prove a failure keeps every stem, retry the failed step to `ready`, interrupt each working state, and reject bad arguments with sentinels.

## What surprised me

Foreign keys are on, so `Begin` needs a user row to exist first. The tests seed one owner before starting episodes. SQLite counts a row set to its current value as affected, so `Fail` on an already failed episode succeeds as a harmless no-op. The single-writer pool serializes racing updates, so the guarded update alone picks one winner.

The concurrency test uses `sync.WaitGroup` with a start barrier instead of `errgroup`, because `errgroup` lives in `go.mod` as an indirect dependency and promoting it would edit a file outside this task. A future task that owns `go.mod` may switch the test to `errgroup` with `SetLimit`.

Retry targets need no stored column, because the caller names the failed step.
