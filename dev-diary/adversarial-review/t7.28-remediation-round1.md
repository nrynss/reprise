## Residue I did not close

When no rendered words exist yet, `renderClockWords` leaves out the 10 ms crossfade at each join.
A word after N joins leads its audio by up to N × 10 ms. The reviewer's pin asserts the join with
no crossfade, "Two" at exactly 1 s, so modelling the fade would fail it. Once analysis stores
rendered words, the page follows those and no arithmetic applies. During a cold open no word
lights, because the opening repeats words the list already holds.

## Contract changes

1. **Playwright pin under `web/tests/`.** The gate runs only `web/tests/`. The gallery spec lives
   beside the page as `web/src/routes/gallery.spec.ts`, with its own config, as the editor's spec
   does. `npm run test:e2e` does not run it. To gate it, a task owning `web/tests/` would move
   `gallery.spec.ts` there and delete `gallery.playwright.config.ts`. The unit cases in
   `gallery-cards.test.ts` do run in the gate and cover the card choice.
2. **Rendered words against the newest render.** `render_words` comes from the latest analysis
   run. No column links analysis words to the render they came from, so a re-render before analysis
   reruns would pair new audio with old words. Only a draft can start a render today. A
   task owning `internal/analysis` and the schema would add a render id to the words it stores, and
   the detail would then filter on the newest render.
