## Positive checks (verified, no finding)

- **F2 of T8.6 round 1 flips.** `Routes()` now contains
  `POST /api/login/signout`. `handlerFor` routes it to the login handler.
  Sign-in, sign-out, then the old cookie resolves as a stranger with a
  fresh guest minted. The committed race tests prove each half.
- **Same body, byte for byte.** `TestSignOutAnswersSameBodyForGuestAndOwner`
  compares full body strings for guest and signed-in callers. Both travel
  through `writeLoginJSON` with `no-store`. No oracle anywhere.
- **Atomicity.** `SignOut` inserts the user row, inserts the session row,
  then revokes the old session inside one transaction. Mint-then-revoke
  order is irrelevant inside one commit. A crash rolls everything back.
  The old session stays valid and the call retries cleanly.
- **Joined-mux workaround is sound.** `loginAll` pairs the subtree pattern
  `/api/login/` (the sign-in pair) with the strictly more specific
  `POST /api/login/signout`. No duplicate pattern panic. No shadowing of
  code or verify: the boot test proves both still answer through the join.
  Unlisted methods (such as `GET /api/login/signout`) stay unrouted, the
  same as the POST-only sign-in pair. `Mount` wraps all three in the same
  gate plus middleware, so `handleSignout` always reads a resolved session.
- **No session fixation.** Both fresh ids come from `keel/id.New`, which
  draws 128 bits from `crypto/rand` per id. The client influences nothing.
  Cookie values stay HMAC signed.
- **Chain entry executes.** The appended
  `playwright test -c src/routes/account/account.playwright.config.ts`
  entry runs green on Chromium (4 passed). The stubbed spec cannot prove
  server behavior, but the Go pins above already do.
- **Double sign-out is safe (observation, not a defect).** The second call
  still answers 200 with the identical body. It emits two `Set-Cookie`
  headers: the middleware interim (revoked in the same request) and the
  final live guest. Browsers take the last. A first-wins client would hold
  a dead guest session, and the guest flow self-heals on the next request
  by minting again. Harmless either way.
