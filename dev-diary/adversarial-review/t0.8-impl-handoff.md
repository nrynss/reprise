a 120 second cap. Every session that could be ended was ended with

outside the repository). It mints tokens through the settings key file
without exporting the key, streams ffmpeg-resampled clip bytes at

## Why the task goes blocked

First, faithful pairing is impossible at tonight's speed. The driver
compares the onset gap in the old recording against the start gap in
the new run with a 40 ms tolerance. The choreography bounds every gap
by host replies. Replies take about 47 s tonight against gaps of 7.52,
13.02, and 6.96 s. Every target would miss by 40 s or more. Streaming
the second clip on time anyway would mean talking over the host, which
breaks the choreography the starts must honestly reproduce. The
remaining budget cannot fund the attempt either.

Second, the done criterion cannot flip without a driver change. The
landed `TestFixtureSessions` treats a present start record as failure.
`internal/align/fixture_test.go` lines 161 to 167 call `t.Fatalf` with
"measured past the evidence gate" when `readClipStarts` succeeds. The
40 ms verdict path (`measureRealSession`) never runs on a real session
directory. The reviews claim the test flips with no driver change, but
the committed code refuses the record instead. Landing `clips.json`
alone would turn the non-live gate red. A follow-up owning
`internal/align` needs to switch the test to the `measureRealSession`
verdict first. That task is not mine to write, and the verdict it
would run is proved already by `TestRealSessionVerdictPath`.

## Surprises

1. An unguarded `main()` call at the bottom of the runner module meant
   two debug imports executed the full three-session run. Both were
   killed partway. The guard is fixed. The accidental sessions account
   for about 300 billed seconds. The handoff records this so the spend
   tally reconciles.
2. The first pacing loop blocked on socket reads and streamed at half
   realtime speed. A short read timeout during streaming fixed it. The
   audio bytes were never the problem. Resampled clip energy matches
   the known-good probe PCM (RMS near 2746 against 2802).
3. Client ping replies must carry a mask. The runner masked its pong
   frames during this work. The probe framing this runner copies sends
   them unmasked, which strict servers may punish with a close.
4. `dev-diary/` is tracked in this repository, contrary to the protocol
   note that calls it gitignored. The worktree therefore contains the
   planning files, and both deliverable files commit on this branch.
   Nothing was written to the main checkout.
