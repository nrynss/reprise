# T0.4 implementer handoff

## What I measured

The batch probe ran live on 2026-09-18. It rebuilt a 19 second 48 kHz stem
with Piper locally, uploaded it, and transcribed it with Universal-3.5 Pro.
One creation call carried entity detection, key phrases and summarization
together. The record at `dev-diary/probes/batch.md` holds every response
shape, the per-word timestamp error, the chapter route and the result
route.

Key results: 52 of 54 words matched with most edges inside 150 ms;
entities returned all five planted names with exact word stamp times; key
phrases returned 15 ranked phrases; summarization answered under
`speech_understanding.response`; chapters came from the LLM Gateway with
`qwen3.5-4b-32k-fast`; DELETE scrubs content but keeps a 200 row reading
`Deleted by user.`; polling carries results while webhooks never arrived.

## What surprised me

The flagship model rejects the legacy summarization fields with a 400 that
names the wrong model string. The fix is the `speech_understanding.request`
wrapper. Entity detection and key phrases stay top level booleans, so two
generations of parameters share one request. The account reaches exactly 1
of 37 gateway models. The docs example model is not among them. DELETE
returns 200 with scrubbed fields instead of 404. A package with only live
tagged test files breaks the non-live gate, so the probe adds
`internal/assemblyai/doc.go` with the package clause.

## Spend accounting

Batch bills 0.21 dollars per hour. The probe made 11 creation calls with
about 223 audio seconds in total, plus 2 gateway chapter calls. Batch cost
about 0.013 dollars. Gateway cost about 0.00024 dollars. Total spend under
0.02 dollars. All scratch transcripts were deleted after reading.

## Contract changes needed

The provider adapter has no owner yet, and two probes now depend on its
package. `internal/assemblyai` holds `live_test.go` from the voice probe,
`batch_live_test.go` from this probe, and `doc.go` with the shared package
clause. Whoever takes the adapter keeps `doc.go` and treats both probe
files as callers of its future client. No other contract change is needed.
Polling is the result route, so no webhook receiver task is needed. The
gateway model pin `qwen3.5-4b-32k-fast` holds until account access widens.
