## Key judgment 1: the clips.json gate is the right call, not a finding

Refusing detector times as starts is CORRECT, and the evidence in the tree
proves it. Measured correlation onsets against `input.speech.started`
offsets give detector lags of +24.3 ms (steady), +74.2 ms (pauses), and
-1046.0 ms (barge-in), re-run here through `TestFixtureSessions -v`. Two
consequences follow. First, blessing detector times would pass steady today
at 24 ms and fail it on any re-record, since pauses already shows 74 ms of
per-utterance jitter on clean turns and barge-in shows the detector firing a
full second late under host playback. Second, detector receipt times mark
when the provider noticed speech, not when a clip started, so they are not
the recorder offsets the done criterion asks to agree with. Using them as
starts would also break the product rule that counts come from stored rows,
never from a convenient nearby signal. The shipped sessions carry no other
start record: `events.json` holds socket events, `timeline.json` holds
provider turn records, `metadata.json` holds integrity facts (verified:
channels 2, dropped 0, 24 kHz, left user, right agent). So the verdict has
no input to verdict on, and the driver fails loudly naming the missing
record instead of inventing agreement. That is the honest shape. The missing
file lives in `testdata/sessions/`, outside this task's `owns`, so per the
loop rules it is a coordination need and can never block an APPROVE.

Coordination need (for the recording lane). Each session directory must gain
`clips.json`: a JSON array with one entry per streamed guest clip, such as
`[{"file":"user-a.wav","start_sec":3.412},{"file":"user-b.wav","start_sec":12.870}]`.
Each `file` is the clip base name. Each `start_sec` is the local clock
reading at the first clip sample, on the same clock the event log offsets
use, with millisecond precision or better. The driver matches entries by
file name, needs at least two, and fails loudly on any other shape. Once
the record lands, `TestFixtureSessions` flips from the loud evidence block
to the 40 ms verdict with no driver change.
