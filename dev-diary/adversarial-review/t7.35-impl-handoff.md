## What was built

`render.KindOf` now takes the concurrency and returns the kind with that
limit, idempotence, a resume hook, and its own attempt cap of three. A value
below one returns `ErrConcurrency`, which names `render_concurrency`. The
binary patch is gone. `finish.go` no longer sets `MaxAttempts` and the old
constant moved into the render package beside the kind it guards.

The setting reaches the kind through the job boot. `openJobs` passes
`loaded.RenderConcurrency` into `jobsConfig`, `startJobs` stores it on the
wiring, and `renderKind` builds the kind from it. An invalid value refuses
the boot before the runner opens. Stale comments that claimed one render
runs at a time now describe the limit instead.

Tests pin each half. `internal/render/kind_test.go` pins the limit, the
attempt cap, and the named refusal. `TestRenderKindFollowsConcurrencySetting`
boots with two and holds two render jobs running at once. Both starts would
fail with `ErrLimit` under a fixed limit of one, and that mutation was run
to prove it. `TestRenderConcurrencyBelowOneRefusesBoot` pins the refusal for
zero and negative values. `TestShippedFilesSetRenderConcurrency` pins that
both shipped config files carry a usable value. The existing restart test
now resumes through the kind alone with no binary patch.

## What surprised us

The scope line names `internal/render/`, `internal/settings/`, and
`cmd/reprise/finish.go`. Threading the setting into the kind needs four
small edits outside that line. `main.go` carries the `jobs` struct, the
`jobsConfig` struct, `startJobs`, and `openJobs`. The kind callers live
there too. No design wires production without touching those lines, because
`finish.go` never sees the loaded settings. The diff adds about twenty
lines there and adjusts one line in `main_test.go`. Please widen the scope
line or split the threading into a follow-up before landing.

The old review probe `TestProbeRenderKindResumes` calls `KindOf` with one
argument and no longer compiles when copied into `cmd/reprise/`. The new
`kind_test.go` covers its assertion directly. No tracked probe needs an
update, since the probes module never builds in the gate.

No lambo tools exist in this environment, so nothing was recorded outside
git. The gate result below is the full record.
