# Implementer handoff: stem alignment

Built the episode clock proof in `internal/align/`. Only that path
changed. Five files, all new. The full gate passes in the worktree.

## What it built

`internal/align/` holds pure functions only. Slices go in and numbers
come out, so every pin asserts exact sample math on generated signals
with no device and no clock.

* `align.go`. `ClockOffsets` carries both stem starts on the shared
  capture clock. `Origin` takes the earlier start as the episode zero.
  `Correlate` finds the integer lag between a provider channel and a
  local stem by normalized cross correlation. Positive lag means the
  stem runs later than the reference. `ResampleLinear` converts rates
  before comparison. `Align` combines recorder starts with one lag per
  stem into a `Report`. The provider channels share one container
  clock, so the gap between the two lags cancels provider path latency
  and must reproduce the recorder gap. `Report.Pass` applies the 40 ms
  limit. `Report.Warning` phrases the failure for display.
* `wav.go`. Minimal 16 bit PCM WAV decode plus a test encoder. Decode
  reads the bytes the buffer holds, so placeholder header sizes still
  decode. It accepts mono and stereo only.
* `align_test.go`. Exact pins on chirp signals with known delays: plus
  137 samples, minus 100, zero, bad inputs per sentinel, exact
  resample values, dyadic offset math, the 30 ms pass and 50 ms fail
  boundary, and an end to end synthetic session where a common 150
  sample path latency cancels to zero drift.
* `wav_test.go`. Round trip, mono, placeholder sizes, and rejects.
* `fixture_test.go`. Driver over `testdata/sessions/`. Each session
  wants `user.wav`, `host.wav`, stereo `provider.wav` with the user on
  the left, and `offsets.json` with both recorder starts. It resamples
  each stem to the provider rate, correlates against its channel, and
  fails the session past 40 ms. Missing layouts skip per directory.

## Fixture status

No recorded sessions exist yet. The driver suite skips cleanly, and
the proof rests on synthetic chirps with sample exact lags. When the
recorded fixtures land, the same suite measures them with no code
change if the layout below holds.

## Surprises

Pure tones make fragile correlation targets. A 440 Hz tone at 8 kHz
repeats every 18.18 samples, and a sidelobe 11 periods out once beat
the true lag on rounding noise. Chirps peak uniquely, so the tests use
swept tones with known delays.

Zero padded truncation cannot show a lead. An early copy of a signal
matches a positive lag exactly over the full overlap, so the negative
lag pin stagges two onsets instead. The sign convention tripped once
during implementation: positive lag means the stem runs later, and a
failing pin caught the inverted pairing before commit.

## Contract changes

For the store owner. `Report` is the row shape producer. It carries
the episode origin, both recorder offsets, both measured offsets, both
per stem drifts, the recorder gap, the measured gap, and the relative
drift with its verdict. Persist those fields when the sessions table
grows alignment columns.

For the render and analysis consumers. Read stem placement from the
stored report, never from the prompt or from stem file lengths. The
episode ships when `Pass` holds. A failed check shows `Warning` and
blocks nothing by itself.

For whoever wires the upload route. The server needs the first block
`contextTime` per stem and the player `cutTime` marks to build the
`ClockOffsets` input. The voice path already emits both shapes.

For the fixture owner. The driver expects one directory per session
with `user.wav`, `host.wav`, stereo `provider.wav`, and
`offsets.json` carrying `user_start_sec` and `host_start_sec`. Any
other layout skips silently, so confirm or rename before relying on
the done criteria run.

No library issue arose. Nothing here rebuilds Keel or Chaaya work.

No shared memory server was reachable from this session, so no graph
recall or write ran. The handoff above carries the full context.
