## Findings

### H-1: the standing end control has no listener and never ends the take

Severity: H.
Where: `web/src/routes/record/+page.svelte:17` to `26` at the reviewed
hash, wiring the button rendered at line `102` to `108`.

What: The effect queries `record-end` once at mount. At mount the snapshot
is preflight, so the live section is not rendered and the query returns
null. The optional addEventListener call then attaches nothing. When the
take goes live the button renders with no listener. A mouse click does
nothing. A keyboard Enter does nothing. The control the handoff calls
enabled and focusable is inert. Outside the warning window no working user
end path remains on the page. The take still ends through the timer, the
warn button, pagehide, or destroy, so the demo survives.

Pin: start a mock take, then either click the standing `End session`
button or focus it and press Enter. Expect the `Confirm end session`
state. Both variants fail on this hash. The notice stays on `On air`.
The scratch specs that measured this were deleted after the run.

Mutation: wire the end button through a one time `getElementById` lookup
at mount, which is the current code. Any fix that reaches the live
rendered button (for example the same document delegation the warn
button already uses) flips both pin variants to pass.
