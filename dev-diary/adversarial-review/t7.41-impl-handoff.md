That start is on the host stem clock.
An interrupt earlier than the planned end shortens the span.

## What surprised us

The persisted timeline is the provider session document, not the live socket.
It records reply text, reply start, reply end, and interrupt.
It does not record `start_ms` and `end_ms` per host word.
Those offsets exist only on `transcript.agent.delta` events, and reconcile does not store that log.
Equal slices are the reconstruction from the bounds the file does hold.

The claim table is created by the reconciler, not by the diary migration.
A process with no claim table, which is every schedule test, still starts the transcript with no host replies.

If stems finish before the timeline blob is claimed, the job stores guest words only.
`ensureTranscript` will not run again once those words exist.
A retry cannot add the host side later.
That race is unchanged on purpose.
Failing the start when the claim is missing would break the schedule tests, which create a session and no timeline.
